# 酷得斯 OA 新版

React + TypeScript（前端）· NestJS + TypeScript（后端）· MySQL 8。
这是旧版 OA 的重写，只参考旧系统的功能和业务规则，不复用旧代码。旧系统的研究报告在 `docs/legacy-research/`。

## 目录

```
packages/shared   前后端共用：导航注册表、权限解析、最低售价公式、登录类型
apps/api          NestJS 后端：登录、统一权限守卫、组织架构、加密、迁移
apps/web          React 前端：方案 B 外壳（顶部一级 + 左侧二级）、登录、我的待办、组合编码
docs              路线图、开发约定、旧系统研究报告
```

## 本地启动

需要 Node 20+，以及本机的 MySQL 8（本机直接装的，或 Docker 都行）。

**最省事：** 本机 MySQL 已启动的话，运行 `bash scripts/setup-local.sh`。它会问一次 MySQL root 密码（只在这次运行里用，不会保存），
然后建库建用户、生成 `.env`（随机密钥，权限 600）、装依赖、迁移、种子。完成后开两个终端分别 `npm run dev:api` 和 `npm run dev:web`。

**手动步骤**（用 Docker 的 MySQL 时）：

```bash
cp .env.example .env        # 按注释填写所有空项（密钥必须自己生成，没有默认值）
npm install
npm run build:shared
docker compose up -d mysql  # 等容器健康后再继续；.env 只指向本地隔离库
npm run db:migrate          # 建表
npm run db:seed             # 创建第一个公司和管理员（密码来自 SEED_ADMIN_PASSWORD）
npm run dev:api             # http://localhost:4000/api/health
npm run dev:web             # http://localhost:5173
```

用 `.env` 里的公司代码、管理员账号和密码登录；首次登录会被要求修改密码。

## 资料模块怎么工作

资料（营业执照、店铺、手机号等 18 类）由**同一套引擎**驱动：`packages/shared/src/resources.ts` 里每类资料一份配置（字段、状态、规则），
列表、详情、表单、校验、导入导出、权限键、左侧菜单都从它生成。新增一种资料只需加一份配置，不用再写页面。

- 数据存在 `resource_records`（字段值为 JSON，状态/标题/唯一键/搜索文本单独成列），引用关系同步到 `resource_links`，变更写 `resource_change_logs`。
- 密码类字段加密且任何接口都不返回，查看明文需要 `resource.<类型>.secret` 权限并留下记录；证件号/银行卡号加密存储，但对有查看权限的人直接明文显示（不做脱敏，靠权限控制谁能看）。
- 图片/附件存七牛（在“系统 → 接口设置”填写密钥）；营业执照可用识别大模型自动填表（同页填写接口地址、密钥、模型名）。
- 店铺经营数据/推广/评分现在手工录入或 CSV 导入（利润、投产比自动算）；营业执照详情的“营收”页签按日期汇总它名下店铺的经营数据。以后接平台接口只需往同一张表写数据（source=api）。
- 组织：“部门与岗位”给岗位授权，“员工与权限”建员工（随机临时密码，只显示一次）和设置个人额外允许/拒绝；非管理员不能授予自己没有的权限、不能改自己的权限、不能动管理员；全部变更写审计。
- 停用/注销/删除必须填原因；还被引用的记录不能删除（先解除引用或改为停用）。
- 只有某一类才有的规则放在 `apps/api/src/resources/resource-rules.ts`（如：店铺绑定的手机号必须已建档、营业执照创建后自动生成手机号/合作人/税务/银行账户）。
- 权限键：`resource.<类型>.<view|create|edit|disable|delete|import|export|secret>`，子记录沿用父资料的权限。
