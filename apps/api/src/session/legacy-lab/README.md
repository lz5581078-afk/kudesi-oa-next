# 旧店铺登录模块本地接入样例

只验证店铺提现登录管理、公司店铺维护的旧实现能否连接新版身份、权限和店铺资料。不是生产接入，不注册AppModule，不覆盖新版页面，不安装或升级用户助手。

## 运行

本机MySQL 8需已在127.0.0.1:3308监听；使用既有本地客户端配置提供数据库凭据，不创建或保存新的密码文件。在仓库根目录运行：

```powershell
node apps/api/src/session/legacy-lab/run-local.cjs D:\OA-Next-Local\mysql-admin.ini D:\work\kudesi-oa
```

运行器只允许回环地址和3308端口。每次创建全新的`session_reuse_next_<随机>`、`session_reuse_lab_<随机>`两库，不复用既有业务库、不删除数据库；创建失败直接停止。执行真实新版迁移、显式的旧会话测试夹具及合成数据，原旧迁移的up/种子/旧OA启动器均不运行。

最终结果摘要写入忽略目录`.local-test/session-legacy-lab-latest.json`。数据库保留以便检查；测试自身创建的临时助手配置目录会被清理，用户既有助手配置和Profile不读取、不覆盖。

## 复用方式

- `lab-bridge.ts`直接加载指定旧项目的`createSessionManagerRouter`，不复制或重写登录任务、设备绑定和凭据业务实现。
- `lab-fixture.ts`只提取旧迁移的静态结构SQL。旧stores/employees以只读VIEW映射真实新版资料/员工；显式映射旧店铺101至新版记录ID，不按名称猜测身份。外部FK在实验模型中省略，内部索引、约束保留；不是生产迁移设计。
- 新版真实JwtAuthGuard、PermissionsGuard和数据库仓库校验员工身份；连接层按两个用途的现有view/manage权限限制操作。现有新版明文密码由manage权限控制，没有另造“明文查看”权限键。
- 旧模块凭据加解密依赖注入新版CryptoService；不会加载旧加密默认值。样例回报只保存白名单进度，错误文本统一为通用描述，避免写入凭据。
- 原版`agent/register-device.js`、`agent/api.js`和Profile映射函数直接参加测试，仅向随机本地端口通信；不是模拟成功返回，也不是安装/启动完整Windows托盘或浏览器。
- 控制器仅供测试宿主使用。桥接函数要求显式`SESSION_LEGACY_LAB=1`，并拒绝production；未启用时数据库套件不加载数据源配置。

## 验证范围

样例覆盖新版JWT、平台身份拒绝、跨公司/工作区、只读权限、请求身份伪造、一次性绑定码、真实原版助手注册和HTTP通信、资料实时映射、双用途凭据及新版加密、领取/等待人工验证/取消/成功/失败回报、合成认证证据校验、终态重放与单用途撤销。

运行器同时执行既有session、session-list、maintenance、session-parity、remote、agent-release数据库回归，以及样例默认关闭测试。

本样例**没有**替换新版页面或接通其API客户端；没有执行真实平台登录、验证码、远程采集/画面/输入/恢复/安全关闭、助手安装更新或财务业务。远程与旧店铺状态写入端点明确404。既有remote数据库回归通过不等于旧链路远程接入完成。

当前用单MySQL连接串行测试，未验证并发请求或只读投影视图的生产锁语义。成功登录证据为明确标注的合成输入，仅用于测试旧验证器，不能当作平台接受或真实登录证明。正式接入前仍需模块内前端契约适配、并发/事务方案、旧远程链路和授权测试电脑联机验收。
