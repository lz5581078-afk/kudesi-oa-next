# 酷得斯 OA 桌面客户端

Windows x64 安装包；Electron 外壳内嵌原聚水潭网页，OA 提供独立售后跟进面板。不依赖聚水潭开放 API。

## 使用（0.2）

- 外层全部为 OA 自有售后列表。默认按申请时间倒序，列可显隐和调整顺序；申请时间、单号、负责人、紧急度及下次跟进支持全量归档排序。源平台未加载或未识别的字段不冒充已有数据。
- 聚水潭默认后台承载，只有主动展开原页面才显示。登录状态保存在本机 Profile；原单退款、收货、拦截仍由人员在原页面执行。
- 「采集连接」核对聚水潭公司后启用最新补采，默认一轮成功后约 60 秒再查询。多个客户端竞争同一来源的一轮短租约，其他客户端等待；掉线后接续同一轮及页次，不分派不同页面或历史区间。
- 最新补采固定时间窗口，保留 10 分钟重叠去重。第一次只查最近一天，未成功不能推进水位；本轮由一台电脑顺序完成分页。虚拟列表须滚动读全并核对条数。
- 历史订单只在操作者本机按完整售后单号或内部订单号查询。查询结果及原平台变化归入同一 OA 档案，不更新最新补采水位，不加入协同队列。
- 顶部常驻采集状态，每 5 秒核实。停止、失败、未连接、无法核实及超过两轮加 15 秒仍无成功记录均显著告警；保留最后成功时间及原因。客户端在线不能替代成功查询。
- 点售后单号进入自有详情，记录处理进度、负责人、下次跟进、证据、紧急度、行颜色及跟踪报告。源数据变更只追加历史，不覆盖人工记录或推进人工版本。
- 跨部门推送复用 OA 通知与出站箱，只授权被分享的这一单。协作人员可以追加处理记录，不会因此获得完整售后列表权限。正式办理复用现有统一售后流程，操作和审批人由流程决定。
- 自动建档允许暂未关联 OA 店铺；发起正式流程前必须核对并关联本公司有效店铺。`after-sales.workspace.view` 访问范围及价格、成本权限仍由服务端校验。
- 默认截图快捷键 Windows `Ctrl+Shift+S`、macOS `Cmd+Shift+S`，支持区域选择、标注、遮挡、复制、保存及绑定售后附图。

网页适配器只读取白名单业务字段，不读取 Cookie、密码和浏览器存储，不保存含令牌链接。登录失效或源页面改版会停止本轮，不能显示为同步正常。关主窗口会留在托盘继续采集，明确退出客户端、电脑休眠或断网后需其他在线客户端接续。

## 开发与打包

安装桌面依赖使用 Node 24：

```sh
npm ci
npm run dev:desktop
npm run desktop:win
```

安装包在 `apps/desktop/release/KudesiOA-Setup-0.2.0-x64.exe`。使用 electron-builder 的 NSIS 1.2.1 工具包，可在 Apple Silicon Mac 交叉生成 Windows 安装包；Windows 安装目录和可执行文件统一为 `KudesiOA`（显示名称保留酷得斯 OA），CI 另测安装与卸载及真实 Electron 剪贴板。

开发时仅接受 `OA_DESKTOP_URL` 指定的本地 Vite 来源 `http://localhost:5173`、`http://127.0.0.1:5173`、`http://127.0.0.1:5186`。安装版固定 `https://lc.kudesi.com`，不能用环境变量改到其他网站。旧版项目只复用已授权的酷得斯图标资产，不复用旧客户端代码。

现有 Web 回归使用 Node 20（生产发布检查保持 Node 22）；Node 24 与旧 JSDOM/Router 的 AbortSignal 存在测试兼容问题。因此 CI 先用 Node 24 安装依赖，再回到原版本运行原工程检查，桌面打包及原生测试独立用 Node 24。

## 与小白 AI 客服共用服务器采集器

商品图片公开链接随售后快照保存到 OA：列表缩略图最多两张，售后和订单详情按各自商品表顺序保存（空位置保留）。页面优先读取已归档链接，不要求本机登录聚水潭；旧记录在后续采集或打开详情时补齐。链接沿用现有公开图片域名校验，实际图片仍由原图片服务器提供。补采其他字段保留图片，商品内容变化但没有新图片时不沿用旧图。发布时先更新 OA 接口和页面，再更新桌面或共享采集器。

在已接入共享队列的小白 AI 客服项目中，执行 `node apps/desktop/scripts/package-shared-collector.cjs <AI客服项目的jushuitan-collector绝对路径>` 将当前 OA 网页读取模块装入现有采集容器的构建目录。由同一个采集器进程使用已登录的公司浏览器会话，在独立标签页只读查询「售后（极速版）」。售后中断时释放租约，下一轮从未完成的页继续。

- `OA_AFTER_SALES_ENABLED` 默认 `0`。`OA_AFTER_SALES_RESERVE_START` 和 `OA_AFTER_SALES_RESERVE_END` 是编码专用时段，默认北京时间 `02:00` 至 `07:30`。专用时段内售后暂停。到点关闭未完成编码任务的专用标签页并记录截止原因。已下载并进入导入阶段的文件继续导入，浏览器同时交还售后。原编码排程应设在专用时段内，窗口外的新编码请求返回 409。
- `OA_AFTER_SALES_URL` 指向 OA 的 HTTPS 根地址。`OA_AFTER_SALES_ACCOUNT` 和 `OA_AFTER_SALES_PASSWORD` 通过服务器的私有配置注入，使用已完成飞书绑定且仅授予售后工作台访问的专用 OA 账号。聚水潭账号继续由原采集器管理。
- `OA_AFTER_SALES_AI_COMPANY_ID` 指定小白 AI 客服中已有登录会话的公司，`OA_AFTER_SALES_OA_COMPANY_ID` 指定归档公司。`OA_AFTER_SALES_SOURCE` 要与聚水潭原页和 OA 已启用的采集来源名称一致，来源间隔设为 60 秒。
- 正常情况下每 60 秒开始一轮，上轮运行较久时等待它完成。OA 的租约仍限制同一来源只能由一方采集，按最新已归档的申请时间向前补 30 分钟，按既有售后单去重。关闭启用开关即可停止服务器轮询。

## 售后快捷筛选

售后单号与复制按钮保持同行。复制优先走受信任 OA 售后页面的原生文本剪贴板 IPC（不开放剪贴板读取或后台采集调用），旧客户端及浏览器使用网页复制兜底。单号下方的蓝色时间框按快照 `capturedAt` 显示最近成功读取聚水潭的分钟数，与 OA 跟进编辑时间分开；“更新”按当前单号和来源公司回查，保存 OA 后重载当前筛选列表，失败保留原时间并显示行内原因。原生复制通道需要更新客户端。

列表的五类快捷筛选读取 OA 已归档字段，与 OA 待处理/撕单/完结范围、搜索及列筛选取交集，服务端先筛选再分页。“全部”仅清除快捷条件。

聚水潭公开前端 `buttonSecondType` 转换为 `quickSearchList:[{type:编号}]`：未发货仅退款2001、已发货仅退款2002、退货待处理2003、待买家退货2007、买家已退货2004。其服务端完整查询条件不可见，目前按公开前端处理阶段实现，尚未完成真实筛选结果对照。

字段对应：`onlineType`=线上类型，`afterType`=可编辑售后分类，`onlineState`=线上状态，`orderStatus`=订单状态快照（售后创建时），`originalOrder.status`=原订单状态（当前）。聚水潭前端处理提示使用历史 `orderStatus`；用户明确要求 OA 快捷筛选仅使用当前原订单状态，历史状态留在人工处理时考虑。不能用运单号推断发货，也不能用售后分类替代缺失的线上类型。

仅退款且等待卖家同意时，原订单状态“已发货”归已发货，其余明确的未发货状态为已付款待审核/发货中（打单拣货）/异常/等供销商|外仓发货。普通退货/退货退款按“等待卖家同意”“等待买家退货”“买家已经退货，等待卖家确认收货”对应后三项；末项兼容原页帮助文案“买家已退货，等待卖家确认收货”。缺失关键字段时不猜测分类。
