# 系统蓝图

## 这套系统是什么
公司所有事务的统一入口：**资料是基座，流程是主线，记账在流程里自动完成，任务告诉每个人今天要做什么**，并融合聚水潭（先统一商品编码，后拉订单算利润）。

## 已确认的决定
- 资料、财务两个板块**沿用旧系统的分组和单据体系**（见下），其余导航由我规划。
- 财务沿用旧的“制单中心”单据体系：每种单据对应一个流程，审批/办理完成后自动记入流水账（先流水账，字段预留科目，将来可升级复式）。
- 聚水潭：先由本系统建商品编码并推送，两边编码一致；之后拉订单、售后等，结合成本算利润。外部写入走出站队列 + 总开关，需单独授权。
- 第一条完整流程：店铺/执照类事务（借执照、开店、换手机号、注销店铺…）。

## 流程引擎与任务中心（已做）
- 流程模板写在 `packages/shared/src/flow.ts`（字段、办理步骤表单、默认步骤），业务动作写在 `apps/api/src/flow/flow-adapters.ts`；新增一条流程 = 加模板 + 加适配器，不改引擎。
- 流程配置：管理员给每一步指定办理人（员工/岗位/部门）、时限、抄送、超时升级对象；保存是草稿，发布后新发起的流程按新版本走，在办的不受影响。
- 办理人规则：员工/岗位必须解析到恰好 1 名在职员工，部门里任一人办理即可，永远不兜底给管理员；管理员不是自动办理人，只能“转交”。
- 办理动作：通过、退回上一步、拒绝、废除（需原因）、发起人撤回/重新提交；业务动作和流转在同一个数据库事务里，失败整体回滚。
- 超时：每分钟扫描，只提醒办理人和升级对象一次（站内通知）；没做到期前提醒、飞书/短信。
- 任务中心：任务和流程待办放在同一张待办表里；手工任务可指派（需 `tasks.assign`）；周期任务每天/每周/每月按北京时间生成，唯一键保证同一天不重复生成，服务当天没运行就不补发。
- 流程是线性的：没有条件分支、并行会签、按金额选审批人；需要时再加。


## Windows 助手（apps/agent）

装在授权电脑上的 Node 程序（TypeScript，playwright-core 驱动本机 Chrome/Edge）。流程：`register`（8 位绑定码换设备令牌，令牌只在本机 `%LOCALAPPDATA%\\KudesiAssistant\\agent.json`）→ `run`（每 5 秒心跳，空闲时每 2 秒领取一条请求，一次只做一件事）。

- 每家店铺一个独立 Profile 目录（随机目录名），登录状态只在本机；同一时间只开一家店铺的窗口。
- 打开店铺：本机登录态有效就直接用；否则用服务器交付的账号密码自动登录；遇到验证码/滑块不硬闯，等人在窗口里完成（最长 30 分钟）；再用“域名白名单 + 页面文字特征，连续两次”确认已登录。支持拼多多、淘宝/天猫、抖音、快手、京东，其他平台明确拒绝。
- 截图请求（capture）：截取当前已登录的店铺页面，multipart 上传到 `/api/agent/requests/:id/upload`，服务端存七牛并记为未绑定凭证；网页保存提现单时再绑定到单据。
- 回报给服务器的文字会抹掉密码；令牌被撤销（401/403）时助手清除令牌并退出。
- 安装：`npm run pack -w @kudesi/agent` 生成 `release/kudesi-assistant-windows`，里面的 `install.ps1 -Server <OA地址> -Code <绑定码>` 完成安装、绑定和开机自启（计划任务）。
- 在线自更新：管理员在“授权电脑”页上传 `npm run pack -w @kudesi/agent` 生成的 .kapkg（服务器自己算 SHA-256、解包校验、版本取自包内，版本必须递增，可撤回）→ “升级/全部升级” → 助手心跳拿到目标版本、sha256、size → 用设备令牌下载（只发给被安排升级的本公司设备）→ 校验大小/SHA-256/包内每个文件 → 解到 `versions/<版本>` → 切换 `update-state.json` 进入试运行并以退出码 75 退出 → 启动器（`launcher.js`，开机任务运行它）拉起新版本；新版本连上 OA 写 `healthy.json` 才算成功，120 秒内不行就杀掉回退旧版本，旧版本启动后向 OA 报告“已回退”（该版本进 bad 列表不再重试）。进度状态 update_status：queued/downloading/verifying/staged/applying/restarting/succeeded/failed/rolled_back，失败原因在 update_error。升级包只更新助手程序，启动器和 node_modules 只在安装时更新（依赖变化会拒绝并提示重新安装）。1.0.0 没有自更新，需手动重装一次 1.1.0。
- 没做：托盘图标。远程协助已做，见下一节。目前除远程协助外，仍是“助手在店铺窗口所在电脑上登录，人在那台电脑上操作平台后台提现”。

## 远程协助（店铺提现里，已做）
店铺窗口需要人工完成验证（拼多多滑块/短信等）而人不在授权电脑旁时，有权限的同事可以在网页里看到并操作“这家店铺的浏览器窗口”。
- **默认全部关闭**，要三道同意才会开始：① 管理员在“店铺提现 → 授权电脑 → 远程协助”里开启这台电脑（可选只观看/可操作，单次最长 5~60 分钟，写日志）；② 电脑主人在本机用 `kudesi-agent remote prompt|auto` 允许（默认 off；prompt 每次弹窗，30 秒内点“是”才同意）；③ 申请人有权限 `finance.session.remote`，并填写事由（2~100 字）。
- 流程：店铺行“远程协助”→ 选模式、填事由 → 助手同意 → WebRTC 连接，画面是店铺窗口的屏幕截图帧（Chrome 调试协议，只拍浏览器页面），操作（点击/按住拖动/滚轮/按键/文字）走数据通道。画面和操作点对点传输，不经过服务器；服务器只做权限、时限、信令信箱（表 session_remote_signals，结束即清空）和记录。
- 时限与结束：默认 15 分钟，申请人可延长（每次 10 分钟，总长不超过 60 分钟）；到点、店铺窗口关闭、网页 45 秒无心跳、助手 30 秒无心跳、电脑被撤销/关闭远程协助、店铺被移除或改绑电脑、管理员“紧急停止”或环境变量 `KUDESI_REMOTE_ASSIST_DISABLED=1`，都会自动结束并写明原因。同一家店铺/同一台电脑同时只有一场。
- 限制：只有平台自己的域名页面会被拍摄和操作（`platforms.ts` 白名单），页面跳走就暂停画面并拒绝操作；只观看模式助手一律不执行操作；助手对网页发来的每条操作重新校验（坐标 0~1、按键白名单、频率上限）。
- 记录：`session_remote_sessions`（谁、哪家店、哪台电脑、模式、事由、起止、时长、操作次数、结束原因）+ 店铺提现“操作日志”里的 remote_* 条目；申请人看自己的，有 `finance.session.manage` 的看全公司。
- 网络：同一内网直连即可；跨网需要在服务器环境变量配置 `WEBRTC_STUN_URLS`、`WEBRTC_TURN_URLS`、`WEBRTC_TURN_SHARED_SECRET`（TURN 账号带时限，按会话生成）。没有做 JPEG 回退通道。
- 代码：`apps/api/src/session/remote.*`、`packages/shared/src/remote-assist.ts`、`apps/agent/src/remote*.ts`、`apps/web/src/pages/finance/remote/`。端到端脚本 `apps/agent/scripts/e2e-remote.cjs`。
