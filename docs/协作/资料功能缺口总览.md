## 跨资料的共性缺口（先补通用能力，一次覆盖多种资料）

1. **删除变成硬删除**：旧系统全部是“归档，可恢复”，有“已归档”页签和恢复；新系统只有永久删除。
2. **即将到期/年审/对账提醒**：执照年审（每年 MM-DD）、银行对账日、商标/授权到期、固定资产保修、聚水潭授权，总览“需要关注”和列表徽标。
3. **引用选择器只取前 200 条且不能搜索**：旧数据有 528 个店铺、328 个手机号，选不到后面的（现有缺陷）。
4. **列表能力**：筛选页签、分类树、列排序、复制、批量操作、导出范围。
5. **关联**：关联属性与跳转；档案关联类型 8 种缩到 2 种；商标→店铺授权整套没有。
6. **导入**：商标/合作人/税务无唯一字段，导入只能新建，无法更新。

## 影响业务的重点缺口

- **商品**：基础编码由“多构成”变成“单商品”，档案保存不再自动同步基础编码；商品专属领取（含申请审批）整块没有；按生效日期的分桶成本记录、运费历史缺；赠品简称/编码简称、materialCode 缺；相似度检查、质量确认、草稿、零值原因库、单位/规格管理、手机扫码传图缺。
- **组合与聚水潭**：聚水潭出站没有真实发送器，上传内容缺款式编码、规格值、基本售价、子商品结构；“最低售价自动同步”和“分类同步”整块缺；组合构成缺 BOM 版本及单位/损耗率/是否进聚水潭/成本处理；赠品别名整块缺；归档和修订的并发保护变弱；对外只读 API 字段和路径与旧版不同。
- **店铺/账号**：店铺批量指派/收回运营、“未指派”页签、一店多手机号、授权商标关联缺；**疑似缺陷**：只选“手机号档案”不填号码文本，绑定会被规则清空（stores 的 matchPhone，自媒体、微信同类）。
- **证照/银行**：税务资料由“每执照+类别”改成每执照一份；U 盾编号、合作人合作范围/起止/预留手机号、执照照片缺失标记、借用“登记归还”缺；借用/使用历史被迁移规则整表排除；迁移对 renewing、商标 normal/active、Q-END 对账日、合作人 inactive 等旧枚举会错转。
- **费用**：费用档案页没有分类目录（378 项/140 类别）；种子导入把默认挂账节点“仓库”（37 项）“公户”（7 项）丢成“不固定”，其中 41 项原为必须关联。
- **快递/人力/往来**：快递手工价格 CSV、加收凭据图片、分区建议 CSV 缺列；人力成本缺“复制版本”；供应商/客户缺相似重复检测、批量移动、分类编码。
- **人事/资产**：固定资产无状态流转/流转记录/盘点；员工缺计薪方式/时薪/薪酬记录/人员记录/导入导出；岗位职责分类 10 缩到 5；部门删除不转移固定资产；职责组缺来源与起止日期，且新系统没有代码使用职责组。

## 建议的补齐顺序

1. 通用能力：软归档与恢复、已归档页签、到期提醒、引用选择器搜索+分页、列表筛选/排序/复制/批量、关联跳转（覆盖面最大）。
2. 数据正确性：手机号绑定被清空缺陷；费用种子的挂账节点；迁移枚举映射；税务每执照多份。
3. 商品与组合：基础编码多构成、组合 BOM 行级字段、赠品别名与简称、商品专属领取。
4. 聚水潭：真实发送器与字段补全、最低售价同步、分类同步（写入需明确授权，走 outbox + 一键停止开关）。
5. 其余各资料的字段与小功能。

## 需要用户拍板的点

多数“旧系统有、新系统没有”的功能，默认都补回。需要你明确的只有：
- 旧系统里疑似死代码/废弃的（旧成本版本引擎、JushuitanGoodsPage、`src/resource-pages`、营业期限到期）是否确认不要；
- 聚水潭写入类功能（最低售价同步、分类同步）是否启用，授权范围；
- 一店是否要绑多个手机号；固定资产要不要加折旧（旧系统本来就没有）；
- 对外只读 API 是否有外部系统在用，要不要保留旧路径和字段；
- 编码长度 48/120、重量单位 kg→克 的迁移取舍。
