# API 配置迁入

旧系统读取只在服务器完成，旧库只读；凭据在内存解密后，以新项目 CryptoService 的当前密钥重新加密。真实数据、密钥及操作报告不进仓库。执行前备份并恢复核验，先完整事务试跑，再以来源指纹及数量一致的报告约束正式提交。

配置对应关系：

| 旧配置 | 新配置 |
|---|---|
| AI 服务商、模型目录、识别默认模型 | ai_providers、ai_models、ai_company_settings |
| 平台聚水潭应用 | platform_integration_apps |
| 公司聚水潭授权与令牌 | integration_settings / jushuitan |
| 公司飞书应用、通知通道、接收人 | integration_settings / feishu；接收人沿旧新员工对照转换 |
| 兼容识别大模型 | integration_settings / vision |
| 对外只读 API Key | finance_api_keys；保留 UUID、SHA256、用途及撤销状态，不生成或恢复明文 |

公司授权的概况由已有接口设置权限保护，按公司读取，仅返回配置存在标记及允许的元数据，不返回应用密钥、令牌、租户标识或嵌套原配置。平台密钥仍由平台后台管理。

聚水潭和飞书的凭据保存不代表真实发送器、OAuth 登录已实现。接口设置页明确显示这项限制；不改同步/通知开关，不创建待发送任务。飞书源启用标志和旧触发起点仅作为原配置保存，不作为新站运行开关。新域名回调需要接入功能后在第三方控制台登记。

旧站运行会话、OAuth 临时状态、历史通知队列不迁。七牛等旧站不存在的配置不编造；现有本地附件不搬动。二次执行必须核对旧新配置，一致则复用，冲突即停止，不覆盖新站人工修改。
