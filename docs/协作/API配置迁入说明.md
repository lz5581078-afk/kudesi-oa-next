# API 配置迁入

旧系统读取只在服务器完成，旧库只读；凭据在内存解密后，以新项目 CryptoService 的当前密钥重新加密。真实数据、密钥及操作报告不进仓库。执行前备份并恢复核验，先完整事务试跑，再以来源指纹及数量一致的报告约束正式提交。

配置对应关系：

| 旧配置 | 新配置 |
|---|---|
| AI 服务商、模型目录、识别默认模型 | ai_providers、ai_models、ai_company_settings |
| 平台聚水潭应用 | platform_integration_apps |
| 公司聚水潭授权与令牌 | integration_settings / jushuitan |
| 公司飞书应用、通知通道、接收人 | integration_settings / feishu；接收人沿旧新员工对照转换 |
| 兼容识别大模型 | integration_settings / vision |
| 对外只读 API Key | finance_api_keys；保留 UUID、SHA256、用途及撤销状态，不生成或恢复明文 |

公司授权的概况由已有接口设置权限保护，按公司读取，仅返回配置存在标记及允许的元数据，不返回应用密钥、令牌、租户标识或嵌套原配置。平台密钥仍由平台后台管理。

真实接入：聚水潭发送器从公司加密配置选择唯一授权账户，校验目标企业，再通过官方白名单接口读取、上传并回查；商品改码的禁用与新建、分类写入阶段均先持久化意图，未知结果不自动重发。写入成功后最多再回查三次（等待 1、2、4 秒），只重读，不重发；持续不一致仍停止并提示核对。实测聚水潭普通商品成本价、采购价只保存元后四位：本地原单价继续保留六位，超出聚水潭精度时在创建上传记录/入队/发送前拦截，不自动舍入，旧队列的此类错误直接停止。普通商品读取补查采购价，并按返回的分类 ID 查询末级名称（回传 category 是显示路径，不按分隔符拆分）；上传按官方字段映射尺寸、其他属性和基本售价，分类要求末级名称唯一且完整路径后缀匹配（允许聚水潭额外的档案目录前缀），再提交末级名称，停用只提交必要标识，避免回传查询专有字段。组合售价更新保留原子商品及其价格，并禁止同步修改实体商品售价。直播订单与退款仅调用查询接口，缺页、缺单、金额冲突均阻断结算。

飞书通知使用各通道的应用凭据，按公司及明确的员工绑定确定接收人；同应用使用 open_id，独立通道使用 union_id。消息使用稳定 UUID 防重，网络结果未知时暂停并待人工核对。现有通知触发规则、出站队列与停止开关继续生效，迁入凭据不会自动开启通知。

飞书登录仅允许已经绑定的员工；禁止按姓名、邮箱或手机号自动认领账号。绑定从已登录账号发起，授权状态在数据库按浏览器、公司、用途和员工核验，十分钟过期，原子消费以防重放。停用公司、停用员工及合作期限制与密码登录一致。上线需在飞书主应用的重定向白名单中添加站点的 `/login` 和 `/feishu-bind`；保留旧站回调。旧身份绑定只沿迁入账本的明确用户对应迁入。

接口设置新增只读连接检查和聚水潭店铺编号清单。店铺必须填入正确的聚水潭编号后才能查询直播订单；不按同名猜测。令牌过期时明确拒绝操作，需要管理员续期；旧新站共用的授权不能擅自轮换，以免影响旧站。

旧站运行会话、OAuth 临时状态、历史通知队列不迁。七牛等旧站不存在的配置不编造；现有本地附件不搬动。二次执行必须核对旧新配置，一致则复用，冲突即停止，不覆盖新站人工修改。
