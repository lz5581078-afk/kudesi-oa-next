# 工作区与备份管理

## 目录和任务生命周期

主仓库固定保留。一个进行中的任务只保留一个开发工作区；同一任务的补改继续复用。多智能体可按不冲突的文件范围协作，需要分支隔离时才创建额外工作区。发布工作区原则上同一时间一个，由负责发布的窗口协调占用，不能自行接管其他窗口的目录。

`bash scripts/collab/start-task.sh <简称>` 优先查找该任务分支已登记的工作区并返回路径。不存在时从 origin/integration 创建；从任何工作区调用都放在主仓库旁，不套娃创建目录。已经存在但没有工作区的任务分支继续使用，不重复分支。不要把创建工作区当成制作备份。

## 日常操作

管理工具需要 Python 3.9+ 和 Git；安全回归用 `npm run test:collab`，也纳入根 `npm test`。以下命令在仓库的任意工作区执行，均不需要业务数据库：

```sh
# 清单：分支、目录、阻止回收的原因。--sizes额外计算大小，不跟随依赖符号链接。
python3 scripts/collab/workspace.py list
python3 scripts/collab/workspace.py list --sizes

# 查看版本备份；只读，不删除任何本地或远程引用。
python3 scripts/collab/workspace.py backups

# 完成任务后停止该任务的开发服务及智能体、核对已提交推送和合并，
# 发布任务还须确认上线与验收成功，再从另一个工作区登记（路径用真实绝对路径）。
python3 scripts/collab/workspace.py accept /绝对路径/wt-任务 --target origin/integration --evidence 'PR编号或验收记录'
# 发布任务必须使用 --target origin/main，不能仅以合入integration作为发布完成。

# 登记后保留3天，先预览；核实目标没有其他窗口/服务在用再执行同一条加--apply。
python3 scripts/collab/workspace.py clean /绝对路径/wt-任务
python3 scripts/collab/workspace.py clean /绝对路径/wt-任务 --apply
```

登记前先 `git fetch origin --prune` 更新远程引用。验收信息存于共用 Git 目录的 workspace-lifecycle/accepted.json，回收记录存于 operations.jsonl，不放入业务源码、不记录凭据。验收不能代替PR/部署实际检查；证据字段由操作者核实。旧目录没有验收记录，一律保持不动；不得用提交日期推断验收日期或回填更早时间。

回收只接受本仓库登记的单个准确路径。主仓库、main/integration、当前工作区、锁定/丢失目录、分离HEAD、未推送、未完整合入、版本改变、未满3天、有未提交/未跟踪/忽略文件的目录都阻止回收。仅允许忽略 node_modules 符号链接，真实依赖目录及 .env、截图等仍阻止回收。压缩合并无法证明完整祖先关系时人工审查，不自动放行。

回收通过 `git worktree remove`，从不使用 --force，不删除分支或远程历史；Git仍会做最终检查。脚本锁只防止多个管理命令并发，不代表编辑器或开发进程已经停止。回收前由操作者确认没有活跃使用者；正在进行的财务还原等任务继续保留。不要使用 rm -rf wt-* 或批量强制清理。

## 验证产物与交接包

本地截图、日志、预览和构建验证输出统一写到主仓库旁 `.local-test/<任务简称>/`，不散落项目根目录，不跟源码提交；普通产物保留14天，发布验收证据放 `.local-test/releases/<发布编号>/` 保留90天。审核/发布结论仍提交到 docs/审计，便于长期追溯。交接包仅用户需要交接时生成，同一交接批次复用，不因反复验证重复打包。

期限是进入复核清单的条件，不是无条件自动删除。清理前确认任务结束、资料可重建及没有业务附件/凭据/原始迁移资料。当前脚本只安全回收工作区，尚不自动删除验证产物、交接包或数据库备份。

## 上线备份

上线前执行以下命令（默认预览，相同main版本复用现有引用）：

```sh
bash scripts/collab/backup-main.sh 发布说明
bash scripts/collab/backup-main.sh 发布说明 --apply
```

沿用上线前备份 main 的规则，备份只是 Git 引用，禁止额外复制整套源码。相同 main 提交已有备份时复用原备份并在验收记录引用；main变动才新增备份。备份命名继续使用 backup/main-before-<说明>-<日期>，避免破坏现有流程。

保留策略为“最近10次 + 最近30天 + 最近6个月每月一个”的并集；特殊回滚、未解决故障、迁移冻结及交接引用永久保护，解除保护须单独确认。旧分支的提交时间不代表备份创建时间，历史创建时间未知的备份不自动清理。`backups` 提供引用清单，人工核对记录后才能做单独的引用清理；本脚本不会删除备份引用。

数据库备份、附件、生产服务器发布/回滚目录、旧系统迁移源独立管理，本规则不改变其保留及恢复要求。

## 现有积压处理

先运行清单并按任务板和其他窗口进度核对；状态过时的任务板行不能直接证明任务仍活跃或已结束。已结束目录先处理本地遗留资料，再登记验收；3天后分批逐个回收。未确认的目录继续保留。不要因目录数量超过目标就删除内容；目录总数是排查信号，不是删除依据。
