# 财务资料查看页对照补齐

日期：2026-10-31。分支：`feat/finance-detail-parity`，基于 `integration`。

用户确认的范围：先补齐商品、供应商、客户、费用、商品基础编码、商品组合编码的查看页。财务单据和查询页详情不属于本次范围；公司店铺维护与提现仍在独立草稿 PR #77。

## 差异与实现

上轮分类与编辑对照没有覆盖查看态。列表点击“查看”仍进入通用右侧详情，这和参考源码中的独立查看窗口不同。

本次仍使用同一个 `RecordDetail` 入口、资料接口、权限和保存链路，只替换六类资料的查看呈现。未增加平行路由、独立资料服务或新的业务数据库结构。

| 资料 | 参考源码 | 本次实现 |
|---|---|---|
| 商品 | `FinanceProductArchivePage.jsx` 的 `renderReferenceProductModal` 查看态、`material-create-drawer.css` | 查看态的分类→基础资料→编号顺序；包装先展示编号；原料成品名、供货来源、容量、库存、生产组成、计量、运装费、成本/采购历史及照片；覆盖原料、自产、原装采购、供应商 OEM、产品包装、OEM 包装、发货物料、自建类型 |
| 供应商 | `FinanceArchivePage.jsx` 的 `renderSupplierDetailDrawer`、`copyAllSupplierBankDetails`、`contact-archive-reference.css` | 分类上下文、编号、基础/联系/收款银行三分区、只读控件；逐项及整组银行信息复制，整组包含供应商名称、账户名称、开户行、银行账号；收款码预览与空态 |
| 客户、费用 | `FinanceArchivePage.jsx` 的结构化档案详情、`styles.css` | 名称标题、基础信息卡片、分类与状态、同屏操作记录；不使用通用抽屉的隐藏空字段/编辑本区 |
| 基础编码 | `FinanceProductBaseCodePageV5.jsx` 的 `BaseCodeDetail`、`product-base-codes-v4.css` | 摘要、商品组成表、成本/采购/重量合计、引用情况、复制新增与编辑入口；马甲使用真实编码的组成 |
| 组合编码 | `FinanceProductBundleCodePageV2.jsx` 的 `BundleDetail`、`product-bundles.css` | 名称/主款式/款式/平台/规格摘要，主商品/包装/赠品/其他/人工分组，数量、成本、销售、重量明细，修改及组成修订入口 |

查看转编辑继续复用现有编辑器。资料关联、子记录、验证历史、操作记录、归档/恢复等额外能力保留在“更多”，避免原有入口丢失。新增系统字段有值时，可在“补充资料”查看。

## 数据与权限

- 组成与来源沿用 `/api/resources/:type`，按页读取完整明细，显式保留已停用的历史供货来源；引用读取失败保留原行，并明确提示，不将读取失败显示为“无组成”。
- 基础编码按单来源/多构成/真实编码区分读取；引用信息复用现有只读辅助接口。
- 成本、售价按独立权限显示。基础编码的已有销售价注册为只读字段，并使用 `product.price.view`，因此接口会过滤无权查看的销售价，不只是前端隐藏。
- 数量乘单价使用共享定点运算，销售单价字段保留分基数 4 位小数（元 6 位小数）；缺失价格和重量显示“未维护”，不补零。赠品销售小计为零。
- 主款式优先读取现有独立值；自动款式可根据统一命名规则的 `+ZP-` 赠品段显示主款式。已人工修改的款式不据此猜测主款式。
- 已停用供货来源不占用“当前最新成本”标记。快速切换记录时丢弃旧请求，避免旧记录覆盖当前记录。列表直达成本子页签不再被加载逻辑重置。
- 仓库模式保留照片查看/追加入口，不读取生产组成和供货来源，不显示成本信息。
- 无数据库迁移，无生产库写入，无外部业务写入。
