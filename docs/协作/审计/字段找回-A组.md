# 字段找回·A 组（经营资料）

范围：营业执照（含借用/使用记录）、税务资料、商标资料（含店铺授权）、合作人档案、资质证照。
对照：10 月 24 日源码（`ResourceDetailPages.jsx` TrademarkResourcePage / PartnerProfilePage，`PhoneNumberPage.jsx` TaxProfilePage / QualificationResourcePage，`BusinessLicensePage.jsx`，`server/index.js` 各 POST 字段，`relation-registry.js`）+ 旧库副本 legacy_full 真实列。
截图：`docs/协作/审计/字段找回-A组截图/before|after/`（1440 宽，演示数据全是编的，库 kudesi_fieldsa）。

## 1. 逐列核对结论

用 mapping-rules + 新字段反查旧库全部列（`business_licenses / tax_profiles / partner_profiles / qualifications / trademarks / license_*_records`）：除技术列（id、company_id、archive_*、status）外，只有下面几列没有落到新字段。

| 资料 | 旧字段 | 旧显示位置 | 新系统现状 | 处理 |
|---|---|---|---|---|
| 营业执照 | business_term_start（3 条有值）、expires_at | 24 号页面已删（“营业期限开始/结束已从最新资料删除”），服务端仍收 | 只有“营业期限至”，缺“起” | 补回 `termStartAt 营业期限起`，迁入器加别名 business_term_start |
| 营业执照 | annual_review_at（99 条） | 24 号已改用 annual_review_month_day | 已由 annualAuditDay 取代 | 不保留，旧完整日期被月日取代（旧代码同样弃用） |
| 资质证照 | scope_type（109 条，全是 license） | 24 号“资质不再直接绑定店铺” | 无 | 纯技术列，不保留 |
| 资质证照 | store_id（4 条）/ 关联 qualification_store（5 条已停用） | 24 号已不用，店铺由执照下店铺自动带出 | “适用店铺”页签按执照派生 | 不保留；已由派生替代 |
| 其余各列 | — | — | 全部有对应字段并在迁入器映射 | 空跑对账见第 4 节 |

## 2. 显示形式还原（重点：商标、税务）

| 资料 | 24 号信息结构 | 新系统改动 |
|---|---|---|
| 商标 | 总览四块：申请中（申请中/已受理）、已申请（已注册）、不可用（驳回/过期/停用/部分通过无效）、合作商标；列：商标、来源、类别、申请人/授权方、申请号、注册号、申请/注册日期、到期日、状态、资料；详情分区：商标基础资料 / 申请与注册进度 / 资料附件（商标照片、受理书、商标证书）/ 关联 / 操作记录 | 去掉自有/合作页签，改四个快捷页签（申请中、已申请、不可用、合作商标，带数量）；详情分区改名同 24 号；列表默认列补申请号、申请日期、授权方；“部分通过”改名“部分通过（无效）”并标红；新增派生列“授权店铺数”；字段名按 24 号（商标来源/商标类别/商标到期日/商标照片/受理书）；到期提醒仍是 90 天内到期标记 |
| 税务 | 按执照一行，分经营/电商两张表；列：营业执照名称、纳税类型、关联店铺（点击查看）、最后报税时间、状态、税务机关、月营业额；详情四分区：基础税务信息 / 报税与经营（最后报税、月营业额、关联店铺）/ 开票与银行 / 联系人与备注 | 详情分区同 24 号；“关联店铺数（点击查看弹出店铺清单：平台、店铺、当前运营、状态）”和“月营业额”并进“报税与经营”（通用能力：派生列 `group` 并入详情分区）；列表默认列加税务机关、店铺数、月营业额；原有“待生成”入口、经营/电商页签保留 |
| 营业执照 | 详情：营业执照信息 / 照片资料 / 实物存放 / 印章资料 / 公司招牌 KT 板 / 公户；列表：登记机关、年审、公户有无、关联店铺、本月营业额 | 分区改名同 24 号；列表加登记机关、公户情况、派生列“关联店铺数（点击查看）/本月营业额”；补营业期限起 |
| 合作人 | 列：编号、合作人、联系方式、关系归属、关联执照/店铺、银行卡有无、状态；详情：基础资料/关系归属/状态与备注 + 关联关系 | 列表默认加关系归属、银行卡登记、关联店铺；其余（法人主体与银行卡页签、关联关系页签）此前已有 |
| 资质 | 列：资质、类型、关联执照、编号、平台登录账号、审核联系方式、备案日期、到期日、状态、资料；详情：资质基础信息 / 关联关系 / 附件资料 | 分区改名同 24 号，列表默认列补审核联系方式、平台登录账号、备案日期、附件；“证书号”改“备案/证书编号”，“备案商品”改“备案产品” |

## 3. 没做、以及原因
- 商标“已申请商标按类别分组 + 类别标签条”：当前列表分组只支持引用字段，类别是文本；用列筛选（按类别筛）代替，未改通用壳。
- 合作人“关联营业执照/关联店铺 点击查看”弹窗：新系统详情“关联”页签与“法人主体与银行卡”页签已列出，列表只加店铺列。
- 导入表头随字段名改名（如“类别→商标类别”），已同步测试。

## 4. 迁入器与空跑
- mapping-rules.json：licenses 追加 termStartAt←business_term_start。
- 空跑（不 --apply，目标 kudesi_fieldsa）：licenses 104、tax-profiles 101、partners 34、qualifications 105、trademarks 53、trademark-authorizations 1，与改动前一致；本组 3 条税务失败（执照被排除/同类重复）为改动前已有。
