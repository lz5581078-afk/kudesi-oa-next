# 采集器录音文件识别 2.0

用户已开通火山的录音文件识别 2.0 标准版，并要求改好、实测可用。原分段接口调用 `volc.bigasr.auc_turbo`，真实返回 403 / 45000030；该资源没有授权。2.0 标准版使用 `volc.seedasr.auc` 的 submit/query，不能仅修改旧极速接口的 resource ID。

## 行为

- 新版 Windows 以 apiVersion=2 提交单声道 PCM WAV 和随机请求编号；OA 使用本公司已加密的 Key，向固定的官方 submit 地址提交。客户端查询本人的任务，显示排队/识别状态，返回的原生分句时间用于录像对齐。
- 请求编号和本机任务进度保存在客户端 SQLite 中。相同输入和编号映射到同一供应商任务；重复上传、网络结果不确定时查询原任务，不自动重复提交。客户端最多20个云端任务同时等待；本地模型仍串行使用。
- OA 的音频属于可重建的临时处理中间文件，AES-GCM 加密存储在既有私有文件卷下的专用目录，不是新的业务主数据。限时加密凭证只允许读取对应录音；不能用于登录或查询任务。查询必须验证当前员工、公司与任务所有者。完成后删除缓存，4小时过期，定时清理；保留256MiB磁盘余量。
- API Key 和 OA 登录令牌不进入音频缓存、任务凭证、响应或日志。供应商错误只映射到固定中文提示，不回传原始错误正文。没有新增依赖、环境密钥、业务表或迁移。
- 旧客户端收到明确的426升级提示，不产生不兼容的空识别结果；实时模式保持现有2.0协议。OA设置说明同步为标准版2.0。
- Windows1.7.2 在主区域显示失败原因和失败片段数量，保留视频及已有文字；失败片段可补识别。实际发行包与源码的一致性和完整功能另行验证。
