# 兼职临时工独立管理与登录设置

用户要求兼职和临时工不进入人员档案，且在兼职与临时工界面能设置登录账号和密码。

人员档案只展示正式员工（兼容未提供用工类型的原列表字段），筛选/搜索/停用显示及人数统计不带入兼职临时工；新增员工弹窗在该页面只允许正式员工，其他组织页面仍可按原规则管理各类型。人员档案CSV接口仅导出正式员工，内部通用人员目录保持所有用工类型，人员选择/岗位/审批/直播等业务不丢失原用户ID或关联。没有删除或迁移人员数据。

兼职页“新增账号并建档”可手动设密码并确认，留空继续生成临时密码且只显示一次。档案详情提供“设置登录账号和密码”：可修改账号、给原本无登录账号的历史人员设置账号；新密码留空保留旧密码，确认新密码后按原逻辑要求本人下次登录改密。原“去人员档案修改”的引导移除。账号/密码输入与普通资源字段分离，不存入资源JSON、资源导出或日志，密码仅以bcrypt哈希存储；审计只记录账号变化和passwordChanged布尔值。

专用POST /workforce/accounts要求resource.workforce.create及org.staff.create；PUT /workforce/:id/login要求resource.workforce.edit及org.staff.edit，改密码另需org.staff.reset。服务端再次检查权限、公司、档案类型/归档、关联用户兼职临时工类型和管理员保护。账号沿用全系统唯一及accountTransaction锁，防同名并发；密码至少8位且不超过bcrypt的72 UTF-8字节。合作期限、停用及必须改密约束保留，不暗中启用账号、不改薪资/权限。
