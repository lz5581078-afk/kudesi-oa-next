# 部分浏览器工作台日期崩溃

用户截图：/workbench/desk，RangeError: Invalid time value，Date.toISOString → ob → KK。只读取得截图对应静态资源index-CAMS35kI.js，其293行对应DailyBusinessPanel计算昨天的shift(todayInChina(),-1)，与仓库源码一致。

根因：todayInChina使用sv-SE地区格式作为机器日期。浏览器的地区语言数据可不完整并回退为11/2/2026等格式，拼接T00:00:00Z后Date.parse返回NaN，toISOString抛RangeError，导致运营工作台渲染失败。截图没有浏览器具体版本/语言包信息，所以未宣称已在该原生浏览器版本实测；已用相同返回值独立复现原代码的相同堆栈。

修改共享todayInChina：当前时间戳偏移UTC+8，取UTC年/月/日并补零，固定输出YYYY-MM-DD。无需Intl或特定语言包，保留北京时间换日口径。财务及其他复用该工具的页面同时得到稳定格式，不改金额/权限/数据库结构或业务记录。

验证：新增8项日期工具回归，覆盖东八区午夜边界、年/月交界、平闰年及缺失语言包；UTC、America/Moncton、Asia/Shanghai三个进程时区分别通过。新增运营每日经营回归模拟toLocaleDateString返回斜线日期，原实现稳定复现Invalid time value；修复后能读取昨日、跨月切换前后日及当天禁用下一日。Node20类型检查、常规全套测试和完整构建通过。无迁移，本地测试不连接生产库。
