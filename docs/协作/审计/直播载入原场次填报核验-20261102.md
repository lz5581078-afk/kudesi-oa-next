# 直播：载入原场次填报核验

用户澄清：核实“载入原场次”是否能带回已填信息。范围为该入口，不新增直接关联排班的填报方式。

## 发现与补正

- 原接口已有公司范围、查看权限校验，并返回场次身份、排班编号、账号店铺快照、产品及各角色填报和订单。前端原先没有完整用这些字段。
- 原特殊核定原因没有回填，现从场次 manualReason 带回；旧场次无该字段时取原填报备注。逐店核定原因保留，不用总原因覆盖。
- 原先上下播时间截到分钟，开播时间丢秒后会触发服务端“须沿用原开播时间”的校验。现展示并提交秒级原值；输入只有分钟时补 :00，浏览器零毫秒规范化至数据库秒精度。
- 销售额取原主播填报，投流费用从对应中控分店行带回，避免用主播的零投流覆盖中控实际值；无主播报告时可回退到已有角色报告，无报告时营业额保持空白。
- 原账号店铺及已选订单直接带回，不要求重新勾选。加载后显示原订单数量和产品摘要；修正逐店核定原因输入框被表格 nowrap 裁掉的问题。
- 原房间、人员、账号、店铺及开播时间沿用事实记录；该限制原本已由后端实施，现界面同步锁定并说明。可编辑营业额、投流、下播时间、订单和原因。已提交审核/已审核场次可载入核对，不能直接补报。
- 载入中、失败或更换编号尚未成功载入时禁止保存；请求版本防止旧慢响应覆盖新编号。新建手工场次保存后再次修改需先载入原记录。
