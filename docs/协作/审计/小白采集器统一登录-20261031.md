# 小白抖音采集器：统一登录与语音配置

目标：Windows 保留本机录制、档案、话术分析和本地模型；使用 lc.kudesi.com 的现有企业员工账号登录。API Key 在 OA 系统 → 接口设置填写，按公司加密保存；电脑不接收密钥。两种豆包识别模式均经 OA 转发。

## 接口和权限

- 复用 `/api/auth/login` 返回的 accessToken；`/api/collector/session` 核验身份、公司启用状态、初始改密要求及 `collector.use`。公司管理员自带此权限，员工由现有权限页授权。
- `GET/PUT /api/settings/integrations/speech` 沿用 `system.integrations.view/edit`。复用 integration_settings，键为 collector-speech；AES-256-GCM 加密，不返回 Key，留空保留原值；修改写无密钥审计。无表结构迁移。
- `POST /api/collector/file` 仅接受两分钟以内 16kHz 单声道 PCM16 WAV 的 base64 和热词；公司及员工身份来自令牌，固定上游地址，关闭语义顺滑并请求原生分句时间戳。
- `WSS /api/collector/realtime` 仅接受 Authorization Bearer，不接受查询参数；相同 JwtAuthGuard 验证。服务端重建语音配置和身份；协议、长度、解压量、队列、连接时长均有限制。每 30 秒核验账号、公司、权限和模式；Key 变更也结束旧连接。单路每五分钟轮换，客户端先结束上一连接，再申请新连接，避免 20 路轮换临时占用 40 路配额。
- 每公司分段和实时共用 1–20 个语音调用槽位。当前单实例 PM2/Docker API 进程内计数；未来横向扩容必须先改为共享租约，不能直接多副本扩容。
- 供应商错误不透传正文和密钥；供应商鉴权失败返回 502，避免被当成 OA 401。不上自动重试，避免重复计费。

## Windows

源目录：本任务的“抖音录屏软件”工作区。版本 1.7.0；新增 OA 登录窗口和公司配置状态，保留录制旁的模式选择。密码只用于登录；登录凭据使用 Windows DPAPI 保存，身份和能力摘要启动后重新获取。不自动关闭旧版窗口、不修改原有档案。旧版本曾保存的本机语音配置仅为兼容回退保留，新代码不使用其调用供应商。
