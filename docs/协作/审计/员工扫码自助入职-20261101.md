# 员工扫码自助入职

用户确认的规则：岗位界面生成两类二维码。通用码扫码填写姓名、手机号、登录密码并选择岗位；岗位专属码扫码只填这三项，岗位由服务端固定。手机号作为登录账号，员工创建后沿用岗位的权限、所属部门和默认工作台；保留人事手工建档。

## 实现

- 岗位列表增加“通用入职码”，启用岗位的行内操作和岗位详情增加“岗位入职码”；需要 `org.staff.create`。同步 PR #127 的岗位工作台权限配置，两个入口保留。
- 二维码支持下载 PNG、复制入职链接、7/30/90 天期限（默认30天）和停用。一个码有效期内可供多位新人使用；关闭生成窗口前应下载或复制，历史记录仅提供状态与停用，不返回原始令牌。
- `/join#令牌` 是手机适配的免登录页，通用码只展示本公司的启用岗位，专属码只展示固定岗位。成功后自动登录；登录失败则显示入职成功并提供登录入口，避免重复提交。
- 公司和岗位从服务端邀请记录取得，不接受客户端指定公司、管理员身份、权限等额外字段。随机256位令牌只存 SHA256 摘要；原始令牌在 URL fragment 中，不进入普通 HTTP 路径或 Referer。公开接口有每分钟限流；失效码、公司停用、发码人停用、岗位或部门停用都会拒绝入职。
- 密码遵循现有至少10位规则、bcrypt 哈希存储，增加72字节上限防止截断；不发放公司管理员身份或个人权限覆盖。
- 注册、手工创建员工和公司申请审核共用 MySQL 账号 advisory lock，直到事务提交才释放，防止跨公司并发创建同一登录账号。员工及审计同事务提交，不记录密码或二维码原始令牌。
- 新迁移 `1762000000000-StaffEnrollment` 只建 `staff_enrollment_invites` 表，无员工数据改写。实体、迁移及全量重迁表白名单已注册；重迁会清理旧邀请，避免保留旧人员/岗位引用。
