# 直播权限、多平台场次与分平台提成

## 已确认业务口径

- 自媒体账号档案增加“直播权限”。只有未停用且显式开启权限的账号可参与新排场和新场次。未配置视为无权限，不自动批量开通。
- 一场直播支持抖音、快手、视频号、小红书等多个平台、多个账号及关联店铺。人员、房间和起止时间属于同一场次。
- 一张表按店铺填报。同店铺被多个账号选中时合并一行；账号必须关联当前公司、同平台的有效店铺。
- 计时工资按场次时间计算一次，不随平台数重复。主播、中控分别保留自己的计时工资。
- 同平台内各店营业额和投流合计后套用现有规则；不同平台独立计算档位、ROI扣减及提成，再汇总金额。当前沿用同一套既有规则，未新增平台专属比例配置。

## 实现与历史兼容

- 新迁移 `1764000000000-LiveMultiplatform`：排场和场次保存账号/店铺快照，报告保存逐店明细；订单、提成及退款核对记录增加平台或店铺归属。已有历史行不回填重算。
- 提成唯一键包含场次、角色、平台；计时工资仍按场次、角色唯一。工资页面和结算单只附加一次工资与分钟数，场次数按真实场次去重。
- 历史单抖音场次继续使用原核算路径；新多平台场次禁止将总营业额按比例拆分。审核手工改数必须给出完整逐店金额和原因。
- 订单按店铺、时间窗服务端回查；同场跨角色可以核对同一订单，同店同订单不能重复计入其他场次。不同店铺相同订单号分别识别。
- 各平台退款只按该平台原提成比例扣减，工资不受平台数量影响，退款汇总不重复计算不同角色。
- 未绑定聚水潭或读取异常的店铺允许开播、填报原因并人工核定。结算检查已审核的核定原因，工资页面、结算明细与导出保留未核对店铺及原因。已报订单的退款读取失败仍拒绝生成不完整结算。
- 关闭账号直播权限后禁止新排场/开播；已有场次的报告、审核和历史核算沿用快照。
- 直播管理审核和流程待办复用逐店表单，审核流程白名单登记 `storeLines`，审核快照保留平台计算和人工核定依据。
- 合入上游下一场排场、产品快照/复用和店铺聚水潭关联功能；导入上次排场保留全部有效平台账号、关联店铺及产品。

## 发布边界

本次不合并main、不部署、不写生产库、不修改现有公司账号授权和聚水潭绑定，不调用真实外部写入接口。上线后需由有资料维护权限的人员在自媒体账号档案中开启直播权限并维护同平台关联店铺。
