# 主播工资与提成独立结算

开发阶段记录：当时仅开发和测试；后续用户授权上线及正式结果见文末。未代操作生产业务结算或真实款项。

## 业务规则

- 工资、提成分别建单，按单人/多人/全部人员和包含起止日的日期范围筛选，场次日期沿用原业务归属日。
- 提成从所属月份的次月10日北京时间00:00起可结算，往月可以补结；未到期、未审核、订单归集未完成或已被占用的明细列出原因。工资不依赖售后接口可用性。
- 新单按具体工资记录、提成记录、日常工作记录占用，草稿也占用；不同人员、不同费用类型可以重叠日期。旧单的明细继续参与防重。
- 生成是核对草稿；提交与最终审批重新验证来源快照及提成日期，提成提交和最终审批复核最新售后。提交携带核对版本，在审批流程持锁时再比对，避免旧页面提交新金额。
- 保留统一流程引擎。退回后重新核对保留原流程关联，撤回或拒绝按既有流程解除关联。新单只冻结关联场次/日常工作，不再封住其他人当天新收入；旧单沿用原期间冻结。
- 已确认单不覆盖或删除，人员名称、场次显示和金额计算依据保存快照。场次详情可查工资/提成关联单号和状态；结算详情可查逐人逐场明细、操作时间、人员和付款记录。
- 实际付款单独登记，可分人分次；凭证必填，累计金额不超过该人本单剩余应付；请求编号幂等，同一公司同一人员的同一付款凭证不能重复登记。此功能仅登记已发生的支付，不调用银行或执行真实转款。
- 结算后退款/工资差错由管理人员按原明细、费用类型、业务凭证和原因创建补扣款调整单，再走相同审批流程。正数补发、负数追扣；原单保留，关联展示调整单。累计负调整按工资/提成分别限制，提成追扣不侵占工资。凭证去重；草稿作废后保留历史并释放凭证和收入占用。已确认负调整可单独登记追回款。
- 后续退款不会自动篡改历史或自动扣款；需按退款凭证登记调整并审批。

## 数据与权限

迁移 `1794000000000-LiveSplitSettlement.ts` 只修改结构：结算范围及快照、原单关联、付款合计、明细释放与原明细关联、三类来源的生成列唯一索引、结算事件表。现有明细默认继续占用；遇到已有重复来源时唯一索引会拒绝迁移，不静默清理历史。

迁移编号脚本建议1793，但本机售后工作区已登记占用1793，本任务使用1794。注册 data-source 并追加 cutover 已知表。迁移回退在有业务记录时拒绝，避免丢失审计历史。

公司和操作人只取令牌。所有业务查询带公司条件，人员、原单、明细跨引用校验同公司。修改接口复用 `live.manage`，金额仍用整数分。公司行锁、提交版本、来源快照和数据库唯一索引共同保护并发。
