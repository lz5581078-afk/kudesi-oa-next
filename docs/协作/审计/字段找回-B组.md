# 字段找回 · B 组「店铺与账号」

范围：店铺档案 `stores`（含领退店 `store-claims`、经营数据 `store-daily-metrics`、推广 `store-promotions`、评分 `store-scores`、资金 `store-funds`、店铺异常原因 `store-abnormal-reasons`、手机号异常原因 `phone-abnormal-reasons`）、自媒体账号 `self-media`、微信号档案 `wechat`、手机号 `phones`（主卡/子卡/绑定店铺/充值提醒）、费用模块 `fee-settings`（手机套餐 / 主子卡费用 / 宽带费用）、宽带账号 `broadband`、账号与服务备忘 `memos`、软件订阅 `software`。

对照依据：10 月 24 日源码（`ResourcesDesk.jsx`、`ResourceDetailPages.jsx`、`PhoneNumberPage.jsx`、`StoreResourcePage.jsx`、`resource-shared.jsx`、`helpers.jsx`、`server/index.js`、`server/migrations/*`）+ 旧库副本 `legacy_full`（只读）里每个表的全部列和 JSON 键。26 日版只在 24 日没覆盖时参考。不复制旧代码和视觉，只还原「哪些信息放在哪一块、怎么分组、关联怎么带出」。

用户特别点名：**自媒体账号按 24 日布局显示**——下面第 1 节单列。

## 0. 做法与结论

1. 先把旧表的每一列都过一遍（`scripts` 里的覆盖检查：旧列有没有被某个新字段的映射用到），再看旧页面的表单/详情/列表/导入导出/筛选，再看旧库里 JSON 真正出现过哪些键。
2. 发现的问题分四类：**A 字段没了**；**B 字段在但放错位置/显示形式不对**；**C 旧版自动带出/联动没了**；**D 迁入器漏映射**（已迁入的数据缺内容）。
3. 本组共处理 **近 90 个字段/显示/关联缺口**（见各节表格）。其中 D 类最伤：**旧库里“店铺绑了哪个手机号”一条都没落到新店铺上**（旧库 289 条有效关联 + 手机号表的 `store_id` 262 条，新店铺档案的手机号档案字段全空，手机号列表的“绑定店铺”整列会是空的），已修。
4. 字段改名统一加了 `aliases`（导入时旧列标题照样认），选项值/键不变，所以已存数据、员工手里的旧导入模板都不受影响。
