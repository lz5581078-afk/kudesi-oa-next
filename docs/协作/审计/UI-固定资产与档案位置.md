# UI：固定资产、房间与档案位置（按 10-24 旧程序重做）

分支 `feat/asset-redo`。范围：资料导航「公司资产」下的 固定资产（`fixed-assets`，同页 资产分类 `asset-categories`）和 房间与档案位置（`locations`，同页 档案项 `archives`）。
旧程序依据：10-24 版 `src/assets-pages/AssetManagementPages.jsx`（`FixedAssetsPage`、`LocationsArchivePage`）和 `server/index.js`；10-26 版只在 10-24 没覆盖处参考。只借功能分区、信息结构和交互，界面和代码为新写，沿用新资料外壳（`res-*`、`rd-*`、`rf-*`、`cat-tree`）。

## 1. 旧页面是什么样的

### 固定资产页
- 顶部有「管理」开关。左边是“资产分类”目录：全部固定资产（带总数）→ 一级分类 → 下级分类，每项带资产个数。进入管理后，每个分类可新增下级、编辑（改名）、删除（要写原因，会解除资料关联）、上移下移；没有分类时提示“点击上方管理，可新增一级分类”。
- 分类可配置“参数”（一行一个，如 CPU、内存、硬盘、系统、序列号）；新增/编辑资产时按所选分类出现这些参数。
- 右边资产列表：列为 资产、分类、使用人、位置、状态、操作；操作有 编辑、领用、归还、维修、报废、记录（展开该资产的操作记录：时间/动作/操作人/说明）。当前分类写在列表头。
- 新增/编辑资产弹窗分四块：基础信息、分类与位置（分类、位置都可以一级级选择）、分类参数、采购与保管、备注。

### 房间与档案位置页
- 位置板块分两种：区域位置（办公楼→楼层→房间）、固定资产储物空间（先选固定资产，再给它建层、抽屉、格/盒等内部位置）。两块各有“管理”：新增一级、下级、编辑、删除（要写原因，会解除资料的存放位置）、上下移。
- 储物空间这一块左边先按“资产分类→固定资产”选出一项资产（显示编号、分类、位置），再看它内部的空间树。
- 右边档案列表：档案、类型、位置、保管人、状态、操作（在库/借出/遗失）；可搜档案编号、营业执照、合同、存放位置。新增档案：编号、名称、类型、关联对象（营业执照/店铺…）、关联资料、存放位置、保管人、状态、备注。
- 新增位置：位置板块、上级位置、绑定固定资产、名称、类型（办公楼/区域、楼层、房间、资产内部位置、层、抽屉、格/盒）、编号、说明、状态。

## 2. 新页面改了什么

### 固定资产（共用资料页，加了通用能力）
| 区域 | 做法 |
|---|---|
| 左侧目录 | 多维度：分类 / 位置 / 使用人 / 部门四个页签，各维度各自的目录和数量；位置维度不列资产内部的储物空间；使用人、部门是平铺目录；有“未设置”提示。手机上折成一行。 |
| 就地管理 | 分类维度有“管理”（需要资产分类的编辑/删除权限）：加下级、改名、参数配置（旧的分类参数）、上下移、拖拽排序、删除（写原因）。位置维度的新增放在“房间与档案位置”。 |
| 快捷页签 | 全部 / 使用中 / 闲置 / 维修中 / 丢失 / 保修将到期（30 天内）/ 没填位置；带数量。 |
| 行内办理 | 每行末尾“办理”列，按资产当前状态给动作（领用、转交、归还、送修、修好、丢失、找回、报废），弹窗沿用详情页同一个办理对话框；报废的显示“已报废”。点按钮不打开详情。 |
| 位置选择 | 表单里的位置、分类用分级列选择器（一栏一级，可搜索），代替单一下拉。 |
| 记录 | 详情页的流转记录、盘点、资产详情接口保持原样，没有改动。 |

### 房间与档案位置（专属工作台 + 表格视图）
默认显示“层级”工作台，右上角可切到“表格”（原资料列表，保留批量编辑、导入导出），选择会记在浏览器里。
- 左：层级树 房间/楼层 → 柜子（固定资产）→ 层位 → 抽屉/格；每项带含下级的档案数，借出或遗失的档案会在树上点红点；顶部搜索位置、柜子、档案（命中档案时展开到它所在位置）；“全部展开/收起”；没有放进房间的柜子、没有归属的储物空间各归入一个分组，不会丢。
- 右：面包屑 + 当前位置的名称、类型；统计块（下级位置、固定资产、档案、借出/遗失）；下级位置/储物空间卡片（点进去）；“放在这里的固定资产”表（含使用人、状态、储物空间数，可新建/查看）；档案列表（可勾选“含下级”，每行直接 借出/遗失/在库 办理，借出和遗失要写原因）；资产上的“其他存放内容”（非核心引用）。
- 管理：树上点“管理”后，选中项出现 ＋下级 / 改名 / ↑↓ / 停用 / 删除；顶部“新增一级位置”、选中处“新增下级位置”“在这里放档案”；快速新增只填类型和名称，默认类型按层级推断（楼→楼层→房间→柜子，柜子→层→抽屉→格）；删除要写原因并沿用后端的“清空引用再删”。显示停用开关。
- 手机：树折叠成一行“位置：全部 ▾”，档案表变卡片。
- 档案项页签：沿用资料列表，加了左侧按存放位置/保管人浏览、在库/借出/遗失/没填位置快捷页签、每行办理。

### 后端和共享配置（只走通用资料框架）
- `packages/shared/src/resources.ts`：`FieldDef.cascade`；`ResourceDef.treeManage`、`treeExclude`；新函数 `browseFilterFields`；固定资产 `filterBy` 改为四维度、新增快捷页签；位置类型加“柜子”；档案加 `filterBy`、快捷页签、类型可搜。`live.ts`：储物类型包含 cabinet。
- `resources.service.ts`：`categoryTree` 接受任一浏览字段；用户/部门平铺目录；`treeExclude`。
- `asset-rules.ts` 新增位置保存规则：区域位置不能放在储物空间下；层位/抽屉的固定资产必须和上级一致（缺省继承）。迁入旧数据时不套这条。
- 没有新增接口，没有新权限键，没改 `navigation.ts`。权限仍是 `@RequireResourceAction`；成本和价格字段不涉及这两类资料。

## 4. 迁入器

`scripts/migration/legacy-adapter.cjs`：旧 `fixed_assets.configuration`（按分类参数名存的 JSON，如 {"CPU":"i5"}）原先拼成一段文字，新资料里没有对应字段；现改为写入固定资产的 `attrs`（参数名→内容，对象值保留 JSON 文本），不再拼文字；不是对象的才作为文字保留。位置类型 `cabinet` 现在是有效值。
在隔离库 `kudesi_asset_dry`（全新迁移+种子，目标公司名与旧公司一致）对 `legacy_full` 公司 3 空跑（`dry-run-rollback`，不写旧库和任何正式库）：asset-categories 22、locations 30、fixed-assets 30 全部通过，这三类零失败；另有 5 条证照的位置引用因旧数据里位置属于另一家公司被如实拒绝（与本改动无关，报告里已逐条列出）。旧库中公司 3 没有 `archive_items`，档案迁入这次没有数据可对。其余失败项（商品成本/组合明细等）是原有财务类迁入问题，与本页无关。

## 5. 迁移影响

无结构迁移（没有新增迁移文件，没有登记迁移编号）。配置字段改动（位置类型 `cabinet`、`cascade`、`treeManage`、`treeExclude`）都在 JSON/配置里。

## 6. 发布后管理员要做的

1. 无需执行迁移。刷新页面即可。
2. 已有的位置数据不用改；旧数据里直接挂在区域下的储物空间会显示在对应区域下，没有归属的会出现在“没有归属的储物空间”分组，可在工作台里就地改。
3. 新建位置时：区域位置不要再放进储物空间里（会被拒绝）；柜子里的层位要先选“固定资产”，抽屉选上级层位即可。
4. 如果要用“参数”：在固定资产分类目录点“管理”→“参数”维护，已迁入的旧配置在资产的属性里。
