# 试播主播由中控确认上下播

用户要求以排场里“新增试播主播”建立的人员为准；没有账号的试播主播无需本人登录，中控上班及下播时必须确认确实由该试播主播直播，中控报告可进入工资、提成审核。

## 实现

- 现有 `LiveManagementService.trial` 已用 `users.live_trial=1`、无登录账号标记试播身份，不靠姓名、账号是否为空或缺报猜测。排场列表及个人工作台携带服务端 `anchorTrial`。
- 只有该排场指定的中控本人可以为试播主播开播，需正常场次核对以及额外具名确认，传入确切的 `confirmTrialAnchorId`。试播主播不能在上播弹窗随意更换，排班变化仍受指纹保护；身份变化/ID不符拒绝。
- 复用现有 `live_session_checkins.confirmation_json` 保存试播主播ID、实际代报中控、排场ID、`trial-control-proxy` 类型；与中控打卡同一事务记录主播计时。它明确表示中控代报，不冒充主播登录。场次试播标记读取该证据，即使日后人员转正式，已确认场次仍保持原身份。
- 下播再显示主播姓名并要求独立确认，服务端校验ID。按点击确认实际时间关闭中控和试播主播计时、结束本场，仅存中控本人报告，另写上/下播审计。
- 原首报30分钟锁场、统一流程审核、聚水潭订单及退款校验保持；试播场次一份有效中控报告即可审核，主播工资取代报实际起止及已有时薪，提成仍归主播本人。正式主播不获得代报豁免。
- 场次详情提示试播主播与代报中控，工资审核快照保留代报身份。未确认的历史场次不按姓名或缺账号自动转换。

## 追加：审核主播业绩明确试播代报（用户授权修改后上线）

直播审核、待办审核和场次详情复用“主播业绩（试播代报）”区域，显示试播主播、从已确认场次读取的实际代报中控、实际上下播、该中控报告的有效营业额及订单数；没有完整订单时显示待核对/待归集，不显示成零业绩。保留真实报告角色，不伪造主播本人报告。审核来源选项同步注明试播代报依据。

代报中控由服务端确认记录关联的started_by读取，包含公司条件，不根据当前排班人员或姓名猜测。新增审核、待办及正式主播不误标回归；上线前执行完整检查并保留main备份。
