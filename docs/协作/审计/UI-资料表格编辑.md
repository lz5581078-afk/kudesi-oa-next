# UI 审计：资料页“表格编辑模式”

范围：通用资料壳（`packages/shared/src/resources.ts` 配置驱动、`apps/web/src/resources/ResourcePage.tsx`、`/api/resources/:type`）里给所有适合的资料类型加“表格编辑”：点一下，整页变成像飞书表格一样的编辑表格，适合批量管理档案。
不碰：任何单个资料的专属页面；已执行的迁移（本任务无迁移）。

## 0. 旧系统怎么做批量编辑（只作功能参考）

旧代码里没有通用的资料表格编辑。能找到的批量能力只有两类：流程里的批量提交（`server/tests/workflow-batch-ui.cjs`、`BundleApplicationCenter.jsx` 的批量申请）和资料列表勾选后的“批量改字段/批量停用”（新系统已有 `BatchBar`）。所以按飞书表格的体验自行设计，保留新系统已有的全部校验和审计。

## 1. 网格库评估（引入前的理由）

| 方案 | 许可 | 体积（压缩后约） | 虚拟滚动 | 单元格编辑 | 结论 |
|---|---|---|---|---|---|
| AG Grid Community | MIT | 600KB 以上 | 有 | 有 | 体积大；多行粘贴、填充柄、撤销、冻结等关键体验在企业版；样式要另外覆盖 |
| react-data-grid | MIT | 约 80KB | 有 | 有 | 编辑器要自己写，粘贴/填充/撤销/列宽持久化也要自己写，剩下的工作量和自己做差不多，但要多一套样式和键盘模型 |
| Glide Data Grid | MIT | 约 150KB | 有（画布） | 有 | 画布渲染，无障碍和测试（jsdom）都很差；我们的单元格要弹出引用搜索、多选 |
| Handsontable | 商业/非商业 | 大 | 有 | 有 | 许可不合适 |
| 自己轻量实现 | — | 约 25KB 源码 | 固定行高窗口化 | 有 | **采用** |

结论：不引入第三方网格库。理由：编辑的难点（每行走服务端同一套校验、失败行回显、冲突、权限、引用搜索）都在业务层，网格库帮不上；窗口化（固定行高 34px，只渲染可见行 ± 8 行）几十行代码即可；DOM 实现可用 jsdom 测试、可访问性（`role=grid/gridcell`、`aria-readonly`、`aria-invalid`）也更好。没有为此写脆弱的 hack：键盘/复制/粘贴全部用标准事件（keydown、copy、cut、paste），不用 `execCommand`。

## 2. 方案与实现

### 2.1 文件
- `packages/shared/src/grid-edit.ts`：哪些资料适合网格（`gridPolicyOf`）、字段能否在网格里改（`gridFieldAccess`）、单元格文本 ⇄ 字段值（`parseGridCell`/`formatGridCell`，金额走 `unit-price.ts` 的 `yuanToPreciseCents`，不经过浮点乘 100）、批量保存的请求/响应类型。前后端共用，只定义一次。
- `apps/api/src/resources/grid-save.service.ts` + `resources.controller.ts` 的一个路由 `POST /api/resources/:type/grid-save`。`resources.service.ts` 只加 `saveGridRow`、`gridRows`、`gridVersionOf` 三个公开方法和 `recordVersion`（`ResourceDto.version`）。
- `apps/web/src/resources/grid/`：`gridModel.ts`（纯逻辑：列、改动、撤销栈、粘贴/填充、保存请求与结果合并）、`ResourceGrid.tsx`（界面与键盘鼠标）、`CellEditor.tsx`（按列类型的编辑器）、`GridBar.tsx`（顶部条）、`clipboard.ts`（Excel/飞书 TSV）、`refResolve.ts`（引用名称解析）、`useWideScreen.ts`。
- `ResourcePage.tsx`：只加“表格编辑”按钮和一处切换渲染（网格替换表格体，搜索/筛选/页签/排序/分页沿用）。

### 2.2 保存接口 `POST /api/resources/:type/grid-save`
请求 `{updates:[{id,version?,data}], creates:[{clientId,data}], archives:[{id,version?,reason}]}`，DTO 白名单（`forbidNonWhitelisted`），一次最多 200 行（前端自动分批）。`companyId`、操作人只取自令牌。
- 权限：路由 `@RequireResourceAction('edit')`；新增行另需 `create`，待删除行另需 `delete`（逐行检查，缺权限的行失败并写明原因，其他行照常）；改证件号/银行卡/密码类字段另需 `secret`（“查看明文”）。成本价格无权限的字段服务端本来就不返回、也不能改（网格也禁止提交）。
- 逐行独立事务：成功的落库，失败的返回 `{ok:false, code, message}`，不影响别的行。每一行都走 `ResourcesService.saveRecord`——与单条新建/修改**同一个函数**：字段校验、唯一性/编号规则、`resource-rules.ts` 的 beforeSave/afterSave 规则、引用校验（同公司）、关联同步、文件绑定、变更日志（备注“表格编辑”）。没有任何直写表的路径。
- 乐观并发：返回的每条记录带 `version`（标题/状态/字段值/加密串/归档标记/更新时间的摘要，不靠只有秒精度的 `updated_at`）。修改行带 `version`，事务里对记录加行锁后比对，不一致返回 `code: conflict`（“刚被别人修改过”），不覆盖。前端冲突行提供“放弃我的修改，载入最新”。
- 删除沿用归档语义：只有配置了归档策略的资料有“删除/归档所选行”，保存时调用现有 `archive`（必须填原因、写日志、可恢复）；没有归档策略的资料不提供网格删除（不硬删除）。
- 不适合网格的资料（11 种，见 `GRID_DISABLED`，原因逐条写在代码里：字段全是系统生成、或必须走专属接口）服务端直接拒绝；商品档案、基础编码不能在网格里**新增**（要选档案类型/生成编码），已有行照常改。

### 2.3 网格体验
- 进入：页头“表格编辑”按钮，仅当有该资料的编辑权限、电脑宽屏（≥861px）、资料适合网格、不是仓库精简模式/已归档视图时显示。进入后每页 200 条，退出恢复原每页条数。
- 编辑：单击选中、双击/回车/F2 编辑、直接键入替换内容；按列类型派生编辑器（完整对照见第 6 节）。
- 只读列：系统计算（`readonly`）、统计列、没有字段权限/修改权限的列、没有“查看明文”权限的证件号/密码列；悬停有原因。showWhen 不满足的单元格斜纹灰显且不可改（改了会让它不适用的字段，会和服务端一样自动清空）。密码类永不回显：只能输入新值，显示为圆点，复制时不带出。
- 键盘：方向键/Tab/Shift+Tab/Enter/Home/End/PageUp/PageDown 移动，Shift+方向键扩选，Esc 取消，Delete/Backspace 清空选区，Ctrl/Cmd+A 全选，Ctrl+C/X/V 复制/剪切/粘贴，Ctrl+D 向下填充，Ctrl+Z 撤销，Ctrl+Y / Ctrl+Shift+Z 重做（撤销栈 100 步，只在未保存改动内；保存或放弃后清空）。
- 粘贴：解析 Excel/飞书的 TSV（含引号、换行）；多行多列从选区左上角铺开；单个值粘到多格选区则整块填充；超出现有行数时询问“是否新增这 N 行”（取消则只粘到现有行）；落在底部空行则全部新增。引用列按名称完全匹配解析，找不到的标红留在格子里；格式不对的内容不丢，标红并写明原因，保存前必须改掉。
- 向下填充：Ctrl+D（选区首行抄到选区其余行），或拖选中格右下角小方块（多行源循环）。
- 列：名称/编码固定在最前、首列冻结（可关）、拖表头右边缘调列宽（按资料类型记在本机）、表格自己的列选择器（第 6.2 节）、点表头排序（服务端排序，沿用现有）、筛选/搜索/页签沿用现有条件。窗口化渲染，一页 200 行只渲染可见的约 25 行。
- 未保存改动：改过的格子黄底+左边条、新增行绿底、待归档行红底删除线、失败行红底；顶部“x 处修改”（改动格数 + 新增行数 + 待归档行数）、撤销/重做、“放弃”“保存全部”“退出表格编辑”（有改动时确认）；有改动时筛选、页签、分类目录、翻页、导入、新增全部锁住，避免换了数据丢改动；离开页面有浏览器确认。
- 保存结果：成功的行用服务端最新记录替换并清掉标记；失败的行留在表格里标红，最右一列（固定在右侧）写明原因；冲突行有“载入最新”。全部成功则刷新列表。
- 手机端：窄屏不做网格编辑（没有键盘和宽度，粘贴/拖拽/多格选择不可用），按钮隐藏（`useWideScreen.ts` 里有说明）；手机上仍可用详情抽屉逐条编辑。

## 3. 不支持 / 留给后续（全字段补全后显著缩小）
已不再有“请去详情页编辑”的字段：多行文本、文件、多引用、属性、清单、日期选择、状态、子表（构成/BOM、借用记录等）、营业执照识别都能在表格里完成（第 6 节）。仍然不能在表格里改的，只有下面这些，原因都写在悬停提示里：
- **系统计算 / readonly 字段**：配置里标了 `readonly` 的（利润、系统生成的标题/来源/标识等，共 114 个，全库 79 种资料 885 个字段里约占 13%），详情表单里同样不能改。
- **没有字段权限的列**：成本、价格等（`permission`）——服务端根本不返回，也不出现在列选择器里；有查看权限但没有 `writePermission` 的列只读。证件号/银行卡/密码类没有“查看明文”(secret) 权限的人不能改（密码类连列都不出现）。
- **保存后不可直改的字段**：固定资产的“使用人”（要通过领用/归还流转，服务端强制，新增行可填）；基础编码被生效引用后的身份字段（服务端校验，失败行会显示原因）。
- **整类资料不开放表格编辑（11 种）**：组合、组合构成行/修订、基础编码构成行、成本记录、运费历史/估算、分区记录、快递识别、聚水潭镜像/上传记录——字段全是系统生成，或必须走专属接口（重算名称、验证、同步），不能绕过。
- **表格里不能新增行的资料（2 种）**：商品档案、基础编码（要选类型、生成编码、录入构成）；已有行的所有字段都能改。
- **子表在浮层里编辑，不进“保存全部”**：浮层里的新增/修改/删除立即保存（与详情页子表完全相同，复用 `ChildPanel`），所以表格顶部的“x 处修改”不含它们。
- **文件上传依赖对象存储配置**：真实上传需要“系统 → 接口设置”里配置七牛；本地验证环境没配，所以浏览器里只验证了浮层、错误提示（“还没有配置七牛云存储…”），上传后的绑定/保存由 vitest 与 API 测试覆盖。
- **文件列/子表列不参与粘贴与向下填充**（文件属于这一行本身，不能抄给别的行）；状态列粘贴只接受不需要原因的状态名称，需要原因的状态要用下拉（会弹原因框）。
- 一页最多 200 行（服务端上限），跨页改动要先保存再翻页。
- 没有“撤销保存”；保存后的修改可在资料详情的变更记录里查看（备注“表格编辑”）。

## 6. 全字段补全：字段类型 × 表格是否可改 × 编辑器

标准：**详情页/编辑表单（`RecordForm`）里能改的字段，表格里都能改**——同一份 `FieldDef`、同一套服务端 `saveRecord` 校验；对照 `RecordForm` 的字段筛选条件（非 `readonly`、有字段权限、`showWhen` 满足、固定资产使用人保存后不可改）逐项核对，表格里一致（`showWhen` 不满足的单元格灰显不可改）。

### 6.1 字段类型对照（括号内是全库配置里该类型的字段数，其中 readonly 的只读）

| 字段类型 | 表格可改 | 编辑器（复用来源） | 粘贴/复制 | 服务端校验 |
|---|---|---|---|---|
| text（335）、phone（4） | 是 | 单元格输入框；手机号规范化 | 文本 | 长度/格式（pattern）/号码格式 |
| textarea（85） | 是 | **弹出多行编辑框**（Enter 换行，Ctrl+Enter 确定，Esc 取消，点外面=确定，显示字数） | 带换行的单元格按 TSV 引号处理 | 同单行文本的长度上限 |
| number（38）、decimal（31） | 是 | 输入框（非负整数/按 scale 小数位） | 文本 | 范围、位数 |
| money（45） | 是 | 输入框，按“元”输入，存整数分；单价类按配置精度（`unit-price.ts` 定点，不经过浮点） | 文本（元） | 整数分/精度 |
| date（58） | 是 | **输入框 + 日历选择**（原生 `<input type=date>`，仍可手输，接受多种写法） | 文本，统一成 YYYY-MM-DD | 日期合法 |
| monthday（1） | 是 | 输入框（MM-DD） | 文本 | 格式 |

### 6.2 表格自己的列选择器
- 列不再绑定列表页的“显示列”。工具栏“列（x/y）”按钮：按 `FieldDef.group` 分组列出该资料**全部**字段（含 `list:false` 的、只读的标“只读”、子表单独一组）；搜索字段名；每组一个“本组全选”（部分选中时半选）；预设“可编辑字段（默认）/列表字段/全部字段/必填字段”，另有“全选/清空”。
- 名称（`titleField`）和编码（`uniqueField`）是标识列，固定在最前、不能取消；首列冻结。状态列紧跟其后（可隐藏）。
- 默认进入就显示全部可编辑字段（再加列表里显示的只读列、状态、子表）；密码类默认不显示，勾选后才出现。选择按资料类型记在本机（`kudesi.grid.cols.<type>`，存储不可用时用默认）。
- 隐藏某列不会丢掉那一列里没保存的修改（保存、统计、联动清空都按“全部可用列”计算）。
- 后端：列表接口一直返回记录的全部字段（`list` 只决定列表默认显示哪些列），没有字段权限的列服务端不返回——`grid-save.db.spec.ts` 里有断言。

### 6.3 状态
- 状态列和详情页的状态下拉同一规则：要“停用”权限、归档的资料不能改；需要原因的状态（注销、停用、解除合作等）选中后立刻弹出原因框，不填不让确认；改动先留在表格里（黄底，悬停看原状态和原因），点“保存全部”时随该行字段一起提交 `status` + `statusReason`。
- 服务端 `saveGridRow` 把字段和状态放在**同一个事务**里：校验失败时字段和状态都不动，成功时只写一条变更日志（备注“表格编辑；状态：旧 → 新（原因）”）。状态变化导致依赖状态的字段（`showWhen: status`）不再适用时，和服务端一样自动清空。
- 批量停用/启用仍走勾选后的 `batch-status`（不变）；新增行不能设状态（沿用详情页：新建用默认状态）。

### 6.4 专属面板与识别
- 构成（BOM）、成本、来源、借用记录等专属面板在详情页是“子表”（`children`/`related`），表格里每个有子表的资料多出对应的子表列，点“编辑…”弹出完整的子表面板（不跳转）；新增行要先保存才能编辑子表。
- 营业执照识别：资料为营业执照时，工具栏多出“识别执照填入所选行”，弹出现有的识别组件（选图/粘贴/拖入 → 识别 → 确认），确认后把识别结果填进所选行对应的单元格（和详情表单一样，仍要点“保存全部”才入库）。
