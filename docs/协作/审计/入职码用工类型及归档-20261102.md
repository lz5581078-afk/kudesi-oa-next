# 入职码用工类型及兼职临时工归档

用户要求解释兼职与临时工页两个新增入口，并让发岗位码时选择正式/兼职/临时工，后两者资料进入兼职与临时工。此前用户已自行处理高宇重名档案问题，本任务不合并或修改任何真实档案。

双入口分别为创建账号后建档、选择已有员工账号建档。保留功能但将普通“新增”明确为“为已有账号建档”，桌面/手机同步，避免误认为两个相同按钮。

通用/岗位入职码新增用工类型，默认正式员工以兼容旧码。兼职可指定合作开始/结束日期，结束日期可空；临时工必须指定合作结束日期；扫码人仍只填姓名/手机号/密码，通用码另选岗位，不能在公共入口改用工类型或合作期。二维码有效期与合作期限独立；码未过期但合作期已结束也拒绝注册。

staff_enrollment_invites结构迁移1773000000000新增类型与日期，不修改已经执行的迁移。账号按码类型创建，非正式员工使用同一EntityManager事务调用ResourcesService.createRecord，沿用通用资料引擎的字段/引用/唯一性/变更日志/用工规则，自动创建workforce档案并关联新账号、岗位、手机号。档案失败整笔回滚，不留孤立账号。计薪标准留待人事维护，不从岗位名称推断正式/兼职，不默认设置工资。临时工合作期约束沿用原登录规则。

发非正式员工码需同时有org.staff.create与resource.workforce.create，注册时重新校验发码人仍在职且具有当前岗位/个人权限，防止权限撤回后继续建档。原手机号全局唯一、公司隔离、无管理员权限的规则保留；不按姓名自动合并人员。
