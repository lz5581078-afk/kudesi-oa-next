# 资料查看与编辑 UI 统一规划及验收

用户要求：资料查看/编辑界面统一重新规划，实现后部署到 lc.kudesi.com。以用户提供的自媒体账号编辑截图和本次当前代码截图为问题来源，保留现有深青色主色与导航体系。

## 问题与规划

| 步骤 | 本次基线证据与问题 | 实施方案 |
|---|---|---|
| 1 查看资料 | `01-before-detail.jpg`：内容在窄详情区逐行堆放，字段和值层次不清 | 分区卡片、字段名在上/内容在下、桌面双列、长文本与多项关联整行展示；保留详情/关联/操作记录及本区编辑 |
| 2 编辑资料 | `02-before-edit.jpg`：复选框继承文本输入框尺寸；多选挤在窄列，几十项撑满正文；部分字段嵌套 label | 独立字段容器及显式 label/input 关联；固定标题与操作栏、正文独立滚动；普通字段双列，复合字段整行；短表单自适应高度 |
| 3 关联选择 | 基线中页外已选项被错误套用第一个名称；搜索和选择的层次混乱 | 已选数量与可移除标签、限定高度的候选区、16px 复选框、长名称自然换行；保留搜索/分页外已选编号，按编号记忆名称；失败提示可重试并保留原值 |
| 4 导航与键盘 | 原分区跳转后选中项容易偏移；弹窗层级可被外层导航遮挡 | 表单实例内独立字段/分区编号与错误定位；只滚动正文；跳转后保留选中分区，手动滚动再跟随；共用表单焦点循环及关闭后恢复焦点；编辑窗口盖过外层详情和导航 |
| 5 专用资料 | 商品、往来资料的旧局部列数与新栅格冲突；客户/费用整窗滚动导致操作栏被推离屏幕 | 保留原业务组件与字段，将公共布局、列宽、控件尺寸、窗口头尾和手机规则集中维护；统一取消/保存顺序，移除重复关闭按钮 |

## 覆盖及边界

- 公共资料引擎的 91 种查看配置、85 种可编辑配置，包括营业执照、店铺、手机号、银行账户、资质、商标、自媒体、微信、宽带、软件、固定资产、位置、档案及各子资料。
- 共用商品/供应商/客户/费用资料、基础编码和组合编码的查看及编辑界面同样纳入视觉规范；原料、自产成品、原装采购、供应商 OEM、产品包装、发货物料、OEM 包装、自建类型的专用字段沿用原配置。
- 数据字段、显示条件、权限判断、敏感字段规则、工资/成本/重量/编码/审批计算及保存接口均沿用既有实现；没有数据库迁移，也不生成或清理业务数据。
- 组织权限管理、通信台账、登录环境授权等专用业务流程保持原有业务组件；其内打开的资料记录使用同一共用资料界面。本次不更改这些流程的权限与执行行为。

## 验收记录

1. **查看：通过。** 全 91 种配置加载验证；浏览器检查自媒体、营业执照、手机号、公司银行卡、店铺、固定资产、账号服务、原料、供应商、客户、费用及基础编码等代表类型。
2. **编辑：通过。** 全 85 种可编辑配置检查单字段标签关联和复合字段不嵌套 label；商品各类型已有回归保留。实测普通资料、商品/往来资料、独立编码编辑窗口没有横向溢出，保存栏位于视口内。
3. **关联选择：通过。** 新增回归覆盖页外已选项、搜索后保留选择、移除前项后其他名称不串位、加载失败重试、自媒体真实编号保存及密码留空不覆盖。浏览器合成资料中从两个关联店铺增至三个，保存后查看与重开编辑均正确回显。
4. **响应式与键盘：通过。** 浏览器检查 1920×1080、1440×900、1280×720、390×844；复选框实测 16×16；手机保存栏可见；普通表单 Tab/Shift+Tab 首尾循环实测通过。截图只用于视觉证据，未把截图视为完整辅助技术验收。
5. **本地工程检查：通过。** Node20 类型检查、完整常规测试、构建通过。完整测试包含 shared353、API312（不接数据库的常规部分）、web939、agent75；新增 UI 回归180项。正式发布流程另执行全量 MySQL 回归与发布回滚检查。

截图均使用本地合成资料，证据在仓库外 `.local-test/resources-ui/`，不提交测试资料。关键对照为 `01-before-detail.jpg` / `07-after-detail-comparison.jpg`、`02-before-edit.jpg` / `06-after-edit-comparison.jpg`；另有桌面、手机及各代表类型截图。已剔除缩放/重绘过程中的未稳定截图，仅采用实际窗口和完整控件可核对的截图。
