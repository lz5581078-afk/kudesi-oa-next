## 实现

- 旧核心以带逐文件 SHA 的快照随 API 构建发布；运行时不依赖旧项目目录，不启动旧 OA，也不调用旧初始化建表。24 份来源文件校验通过后才加载。
- 新版既有页面通过模块内适配层调用原核心的绑定、凭据、登录任务、进度、取消及更新协议。保留新版资料 ID 与旧协议 ID 的明确映射、负责电脑 CAS，发现身份变化或引擎错误时停止，不静默回退另一套数据。
- 原远程窗口、采集与信令核心复用。宿主补充新版当前权限、用途和设备策略；票据校验精确会话，撤销权限后取消待执行输入。原 JPEG 兼容模式、恢复和安全关闭流程保留。旧核心只支持控制模式及可续期的 10 分钟租约，页面不展示不支持的只读模式或时长编辑。
- 两用途共用同一实现，通过公司和 workspace 分开管理设备、凭据、请求、远程及审计。公共店铺档案只有一份；维护状态更新继续走新版资料事务，不直接写投影视图。
- 提现截图复用实际 JPEG 帧，通过新版 FilesService 形成凭证附件；只授予查看加制单/管理权限的截图租约不能获取 WS 控制权限。支持管理员已打开的共享闲置浏览器供制单员截图，不改变浏览器所有者或 Profile；已有远程占用则明确拒绝，不抢会话。上传后重新锁定、核验授权，失败补偿附件，重复领取不重复生成。
- 新迁移 `1777000000000` 仅建立 `sm_legacy_` 会话表、映射、桥接及投影视图，无种子或自动业务迁入。通过真实双连接验证 MERGE 视图行锁阻止底层资料更新；非空数据拒绝 down。
- 共用入口仅追加 AppModule 注册、迁移登记、构建快照拷贝和旧帧路径 1MB JSON 限额。旧帧之外维持原解析限额；切换后只封闭原 native 登录/远程入口，提现凭证与单据接口仍保留。既有整库重迁的精确表清单补登记这 17 张表：空结构不阻断原导入，任何表已有数据则拒绝整库清理，并在删除前用 RR 当前锁定读防并发写入被清除；没有重写其他模块业务。

## Windows 助手

基于可用的 0.3.44 核心制作兼容版 0.3.45；37 份来源文件仅 8 份适配。Profile 键增加服务器 origin、公司及用途，不再仅以店铺数字编号索引。旧 Profile 和数字条目保留，但不会自动作为不同环境/用途的回退。注册和心跳必须收到服务器用途并成功保存后才可领取任务；用途漂移拒绝继续运行。按用户补充要求，绑定窗口预填 `https://lc.kudesi.com/`，无显式地址的注册默认同一新站；不自动覆盖原已绑定配置。

复用原包 Node、Playwright、.NET 采集和原生远程组件，不重新编译原生核心。打包器核实原安装包、来源清单、覆盖文件与成品 SHA；安装 EXE 与完整更新 ZIP 配套生成。Windows PowerShell 5.1 的包内 `.ps1` 需 UTF-8 BOM，正文保持来源一致，变换记录在打包证明中。产物为未签名测试包，尚未安装。

## 切换边界

默认仍为 native，新增代码不会自动切换生产。`KUDESI_SESSION_ENGINE=legacy` 是实例级开关；同实例所有需使用两模块的公司须先核对并准备，不能按单公司随意开启后影响未准备公司。

显式 CLI `apps/api/dist/session/legacy-adopt.cli.js` 默认仅预览。执行迁入要求同代码/同来源预览、目标库/公司确认、备份 SHA 和已核实的旧店铺最大编号；原 live 请求、远程和更新阻止切换。复制的原设备为 revoked，不迁入可用令牌、不回放任务。迁入后 native 源发生业务漂移会拒绝引擎访问，不覆盖任一侧。

旧来源账本店铺 ID 必须明确且唯一；无账本的新店使用 `2**40 + recordId` 保留段。正式切换前须核对旧来源 ID 域，不能假定任意旧本机条目都已验证。工具准备的是新版当前已有登录资料；旧 OA 公司维护等尚未迁入的数据仍需只读盘点和单独批准迁入，不声称已自动补齐历史。

部署时需同时放置 EXE、ZIP 和 `latest.json`，设置 `KUDESI_LEGACY_AGENT_ASSETS` 指向经校验的资产目录，并核对原远程 ICE 配置。没有 ZIP 或摘要失败时不提供升级，但有效安装包仍可下载。先部署服务端与匹配资产，再让用户安装、绑定测试电脑。
