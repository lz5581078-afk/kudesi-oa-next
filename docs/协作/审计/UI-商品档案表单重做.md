# UI：商品档案新增 / 编辑 / 详情重做（对照 10-24 旧版）

分支 `feat/product-form`。依据：旧版 `FinanceProductArchivePage.jsx` 的商品抽屉（查看、编辑、新增是同一个抽屉）、`saveProduct` 校验、`product-code-utils`、`archive-quality`、`gift-aliases`、发货物料重量组件。旧代码只作参考，没有复用。

## 1. 做法：一份布局，三处共用

- `packages/shared/src/product-layout.ts` 是唯一的布局配置：每种档案类型一套 分区（顺序、标题、说明、步骤号）→ 字段 / 功能块；这一类里的叫法、必填、说明、“有值才显示”都在这里覆盖。
- `resolveProductSections(values, {canUse})` 按当前取值和权限解析出“这一刻该显示什么”。**新增表单、编辑表单（含详情“编辑本区”）、详情页都读它**，显示条件只在这一处判断。
- 字段本身（类型、选项、权限、成本脱敏）仍在 `finance-resources.ts` 的 `finance-products` 里，没有另起一套；权限键、编码规则、档案类型不变。
- `productFormProblems()` 是旧版 `saveProduct` 校验的前端版：逐项标出缺什么（含供货来源、生产组成、容量、重量），服务端仍是最终裁判。
- 功能块：分类、编号预览、供货来源行、生产组成行、重量块、成本预览。供货来源 / 生产组成在表单里直接增删改，保存档案后按差异落库（`ProductFormParts.tsx`、`BomDraft.tsx`），新增和编辑是同一个组件。

有意没做（原因）：
- 旧版“自建类型”的类型管理入口：新系统在档案首页的“管理顶级分类”，不放进单个商品表单。
- 构成成本/重量的逐行实时汇总（旧版 `breakdown`）：布局里留了 `breakdown` 块位置，目前由“总成本预览 + 保存后构成页签汇总”承担，实时逐行汇总放后续。
- 分类选择的“快速新建分类”：仍走“管理分类”入口，没有搬进表单。

## 3. 各档案类型的分区矩阵（顺序即页面顺序）

| 类型 | 分区（顺序） |
|---|---|
| 原料 | 所属分类 → 系统自动编号 → 赠品简称设置 → 原料基础信息 → 原料成品名 → 供货来源 → 系统规格与重量 → 运费与装卸费 → 总成本价 → 商品照片 |
| 自产成品 | 所属分类 → 系统自动编号 → 01 自产成品基础信息 → 02 生产资料与成本（原料/产品包装/OEM包装/人工）→ 03 计量与成本结果 → 运费与装卸费 → 总成本价 → 商品照片 |
| 原装采购 | 所属分类 → 系统自动编号 → 赠品简称设置 → 外购成品基础信息 → 采购计价（系统规格、重量、供应商、采购价）→ 运费与装卸费 → 总成本价 → 商品照片 |
| 供应商 OEM | 所属分类 → 系统自动编号 → 赠品简称设置 → 01 外购成品基础信息 → 02 供应商OEM组成（OEM包装）→ 03 采购计价（含 OEM 包装重量、原料采购价）→ 运费与装卸费 → 总成本价 → 商品照片 |
| 产品包装 / OEM 包装 | 所属分类 → 包装编号 → 包装基础信息 → 容量组 → 生产与重量（印刷公司、重量必填）→ 库存与采购价（含系统规格）→ 运费与装卸费 → 总成本价 → 商品照片 |
| 发货物料 | 所属分类 → 赠品简称设置 → 发货物料基础信息 → 发货物料编号 → 供货来源（含各来源系统规格）→ 物料重量（必填，克/千克/斤，默认千克）→ 运费与装卸费 → 总成本价 → 商品照片 |
| 公司自建类型 | 分类与状态 → 商品编号 → 基础资料（含重量必填）→ 采购与成本 → 总成本价 → 商品照片 |

必填差异（由布局覆盖，类型矩阵有单元测试 `product-layout.test.ts`）：自产成品“名称规格 / 名称单位”选填；原料、发货物料品牌选填；采购价对外购、包装类必填；运费、装卸费除自产成品外必填（无成本编辑权限的人不要求，与服务端一致）。

## 4. 优化（不是照抄）

- 分区左侧锚点 + 错误计数，必填没填时提交前就逐项标红，含供货来源、重量、容量。
- 编辑也能直接改供货来源和生产组成；复制新增会带上被复制那条的供货来源和构成（不带行号），编号、赠品简称、库存、照片等不带。
- 详情的分区、顺序、叫法与表单一致；“编辑本区”只打开这一区。
- 重量块：自动换算说明、人工修正开关、克/千克/斤换算后实时显示折合克数。
- 手机 390 宽：分区变横向滑动标签，来源/构成行变卡片，底部按钮两列排布。

## 5. 服务端与迁移

- 包装类：规格数量、单位取“容量”第一行（如 500ML）；写不出来时提示“容量第一行请写成数量+单位”。
- 自产成品规格数量可不填；系统规格 `purchaseSpec` 对原料、自产成品、外购、产品包装、OEM 包装保留。
- `weightUnit` 只对包装类、发货物料保留，其余清掉。
- 迁移适配器：旧包装类重量按“重量输入单位”换算（旧库 14 = 14 克，之前被当成千克变成 14000 克），并带上 `weightUnit`；发货物料仍是千克。`legacy-adapter-products.spec.ts` 加了回归用例。只对 `legacy_full` 只读演练，没有写任何库；没有新增迁移（`weightUnit` 是配置字段，值存在 JSON 里）。

## 6. 需要用户确认

1. 旧版公司自建类型的重量是否一律手填？目前按“手填必填”处理。
2. 自产成品“系统规格”目前必填（旧版如此）；若业务上可不填请告知。
3. 构成逐行实时成本汇总是否需要在表单里做（目前保存后看汇总）。
