## 一、采购申请中心（`flow.purchase`，页面“采购申请中心”）

### 1.1 旧功能清单 + 新实现方案

旧系统：运营提需求；采购完善方案；老板审批；出纳登记货款（新付款或占用已有预付款）；财务确认预付款；按批次发货 → 到货 → 实收 → 质检；质检异常可重检、退回换货、折价接收、终止并退款；申报运费装卸费；财务结算入库（冲抵预付款、费用分摊、更新采购价与物流成本）；支付费用；未到货的回到发货；申请人可申请变更或终止；列表上看到每张采购停在哪、到货进度、异常。价格和付款只给办过金额步骤的人看。

新实现：采购是统一流程引擎里的模板 `purchase-request`（15 个步骤，全部锁定，办理人和时限由流程配置决定）。旧系统写死在代码里的分支，用引擎的适配器钩子表达：`nextStep`（条件流转）、`returnTarget`（退回去向）、`keepStateOnResubmit`/`onResubmit`（变更时保留已付款状态）、`FlowService.redirect`（申请人变更/终止）。采购状态存在流程载荷的隐藏键里，对外只经 `/api/flow/purchase/*` 按权限脱敏后返回。资金动作全部用已有的财务单据引擎：预付款单、采购入库单（含预付款冲抵）、费用单，红冲用于退款。

### 1.4 有意不同（≠）

1. 退款用“替换一张预付款单再红冲原单”实现，净额退回原付款账户；占用的已有预付款是“释放”，不产生资金退款。
2. 运费、装卸费不计入库存成本，而是作为费用单（费用项目名称为“运费”“装卸费”）支付，同时按分摊结果写入商品的运费、装卸费成本字段。
3. 旧系统的“挂账草稿”不做：入库、冲抵、费用都在结算时一次过账，不留半成品单据。
4. 步骤顺序和办理人不再写死，由流程配置决定；条件分支由适配器钩子给出。
5. 采购列表直接复用统一流程的列表接口，不另建采购表。

## 二、专属品申请（`flow.exclusive`，页面“专属品领取”）

### 2.1 旧功能清单 + 新实现方案

旧系统：选一个基础商品，写领取原因提交；审批人审批时设定专属期；通过后到期前其他人不能再领；可看专属记录和历史；有权限的人可取消专属；已被占用或申请中的商品不能再领。

新实现：流程模板 `product-exclusive`（已有）+ 页面 `ExclusivePage` + 接口 `/api/flow/exclusive/*`。

### 2.2 对照

| # | 旧功能 | 新系统 | 状态 | 测试 |
|---|---|---|---|---|
| 1 | 分类、关键字、只看可领取；标出谁专属到何时、谁申请中 | ✓ | ✓ | `exclusivePage` 不可领取的商品点不了 / 搜索与分类 |
| 2 | 缺项提示、提交前确认摘要、提交后打开流程详情 | ✓ | ✓ | `exclusivePage` |
| 3 | 审批时填专属期：天数或自定义结束日 | 二选一（天数或结束日期）；结束日按当天 23:59:59（北京时间），必须在将来且不超过 3650 天 | ✓（结束日只到日期，见 ≠） | `product-exclusive.db` |
| 4 | 通过后到期前别人不能再领；同一商品不能同时多人申请 | ✓ | ✓ | `product-exclusive.db` |
| 5 | 专属记录与历史；取消专属要写原因，历史保留 | ✓ 权限在服务端检查 | ✓ | `exclusivePage` 记录与取消；`product-exclusive.db` |
| 6 | 运营默认有页面权限 | `flow.exclusive.view` 加入运营专员默认岗位 | ✓ | 类型检查 + 页面测试 |

≠：自定义结束时间旧系统可以精确到分钟，新系统只到日期（当天结束）；旧“专属授权”数据不迁移。
