# 工作台直播按钮与运营身份

分支feat/live-desk-role-toggle，PR #231（integration）；本轮用户要求修改，未授权发布生产。

主播、中控、运营本人岗位工作台使用同一上播/下播按钮，依据服务端本人实际打卡状态切换，单纯被排入场次不会误显示下播。上播后原位置显示下播，点击直接进入本人对应身份的下播表单，完成后恢复上播。浏览器标签消息、回到页面以及定时刷新同步状态，丢弃过期读取结果。

运营点击上播先选择身份，默认中控，不展示提成比例。运营选项标注“本场有中控时才可选择运营身份”；只有已有其他中控本人打卡且未开始下播的可加入场次才开放。后端再次校验公司、真实岗位、实际中控、运营席位、本人已有打卡及身份，拒绝越权、抢占、并发换身份。运营可以认领空缺中控席位；原本排为运营但选择中控时清理本人重复运营席位。

运营上下播复用现有场次、打卡记录和审核流程；运营下播按实际提交时刻记录，销售填报保留现有业务表单。保留传统运营中控只计提成规则、首报30分钟锁场和人事审核。本人工作台入口依据实际运营岗位开放；扫码页面由现有服务端角色/公司/本人校验控制，不授予直播管理或人事审批权限。无数据库迁移，不修改人事现有授权。

验证：Node20类型检查、常规全套和构建；隔离MySQL直播/通知/退款/工作台权限5组52项通过。前端专项验证原按钮上播后变下播、下播后恢复、未打卡不误显示、默认中控、没有中控禁用运营、标注且无比例、按运营身份加入以及焦点恢复刷新。390宽度本地合成页面验证默认身份和原按钮切换，未写生产业务、未发真实通知；截图仅保存在本机.local-test/live-role-toggle。
