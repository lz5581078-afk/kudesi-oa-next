# 直播工资管理改版

分支：`feat/live-payroll`。按用户确认的范围开发；尚未部署生产。

## 页面与操作

- 全览南侧在上、北侧在下；房间卡片加高。负责人和房间产品为房间长期配置，由有 `live.manage` 权限的人编辑。卡片预留主播、中控姓名，显示运营、抖音号、彩色状态、开播/预计下播/已播时间和直播进度。临时场次没有预计结束时明确说明，不虚构进度。
- 排场按全部启用房间展示，每个房间列当天场次，空房间保留新增入口。入口带出当前日期和房间，新增/编辑表单双列排列，手机单列。
- 排场可选择已有试播身份，或填写姓名与时薪新增试播主播；保存后自动选中。试播身份使用没有账号、密码认证或岗位权限的稳定人员主键，不创建兼职用工档案。无账号人员由人事补报上下播与业绩，再提交审核。
- 主播工资、中控工资分别合并时间工资和提成；运营提成独立展示。支持按月/日期范围、按人员筛选与明细导出。保留原 `commissions` 页签链接到主播工资的兼容。
- 人事补报使用 `live.manage` 权限。可新建历史场次，或载入已有未审核场次补报；主播、中控、运营可以填不同销售额，投流由中控报告承载。填写订单号时服务端重查订单及金额；不填订单时必须有特殊原因，结算报表明确标注未核对订单。经办人、原因、修改前报告写入审计，仍走 `live-session-review` 审核。
- 提成规则明确显示运营比例。未用于核算的版本可编辑；已使用版本通过指定新生效日期另存，历史快照不改；规则仍带试算。
- 直播弹窗通过 portal 挂到 body，避开页面动画造成 fixed 偏移；手机头尾固定、内容滚动，嵌套试播弹窗的 Esc 仅关闭最上层。

## 工资与结算口径

- 主播与中控分别写入计时工资记录，按各自时薪/计薪起止时间计薪。中控默认结束时间取本人下播报告，审核可调整；档案无计时时薪则必须填写。运营兼任中控仍不另计运营提成。
- `工资结算` 默认按月，也可选起止日期。收入按北京时间的场次开播日归属；跨日场次不会拆开重复计入。合计为时间工资 + 原提成 − 按原比例扣减的退款提成。退款不扣计时工资。
- 结算会重查每场已保存的订单及售后。取消订单按整单退款，累计已完成退款，不含换货/补发/维修；查询缺失、重复冲突或接口异常拒绝生成。所有已核对订单（含无退款订单）的状态、售后依据、核对时间都保留在报表中。
- 工资报表、订单售后报表分别导出。人事无订单特殊核定的场次在工资报表与页面显示来源和原因，不伪装为聚水潭核验通过。
- 所有结算单日期范围不能重叠（包括未提交草稿）；同范围重新核对更新原单。提交后锁定对应日期，月份内其他日期仍可处理；范围结束后才能完成审批。
- 外部查询前后核对收入、计时工资与订单快照；提交/审批时再次检查来源数量及工资金额，避免核对过程中发生变化。流程模板键保留 `live-settlement`，显示名改为直播工资结算审批，审批人继续在统一流程配置里配置。

## 数据结构与兼容

新增结构迁移 `1761000000000-LivePayroll.ts`，已在任务板占号及 data-source 注册：试播标记、房间配置、人事补报来源/经办人、中控工资角色、结算日期范围与时间工资快照。迁移仅改结构。

旧工资记录角色默认主播；旧月结按原 month 还原日期范围，保留原已结算金额，不自动追加未核算的中控工资，不改历史提成、工资或审批。新增工资结算使用新字段。

统一迁库工具 `migration/cutover.ts` 仅追加新表白名单，兼容结构检查。没有执行任何生产迁移、清理或导入。
