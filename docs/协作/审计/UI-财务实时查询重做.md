# UI·财务实时查询重做（按 10-24 旧版）

分支 feat/fin-query，无迁移。范围假设：用户说的“试试查询”＝财务导航里的「实时查询」分组（库存查询、现金银行查询）；新系统该分组还有“未完全结算收付款单”“收付款结算明细表”两页（旧版没有），功能不变，统一换成同一套查询页版式。
旧版源码：`src/finance/FinanceOverviewPages.jsx`（`FinanceInventoryQueryPage`、`FinanceCashBankQueryPage`）、后端 `server/modules/finance/posting-routes.js`（`/api/finance-posting/inventory`）、`/api/resources/page-workspace/bank-overview`。

## 共用组件
`apps/web/src/pages/finance/query/QueryKit.tsx`：页头（标题+说明+数据时间+刷新+导出）→ 查询条件条（查询/重置，回车查询）→ 汇总卡 → 面板（可折叠）→ 表格（平铺或分组带小计、合计行、行选中；390 宽自动变卡片）。账户相关小组件在 `query/AccountParts.tsx`。样式追加在 styles.css 末尾 `.qk-*`。

## 对照表：库存查询
| 旧版 | 新系统 |
|---|---|
| 查询条件：商品（多词）/仓库（文本）/库存状态（全部、正常、缺货） | 已有并保留：商品多词（服务端改为每词都要命中名称或编码）、仓库改为资料选择器、状态同旧版；新增“截至日期”看历史库存（此前已有） |
| 查询、重置按钮；未查询前提示“请先输入查询条件” | 改成与旧版一致的“查询/重置”（改条件后点查询或回车才发请求）；进页面自动查一次全部（优化：不再空白等待） |
| 表格：商品编码、名称、仓库、数量、单位、库存成本、平均单位成本 | 同列同序；成本两列由服务端按 product.cost.view 决定是否返回，无权限整列消失 |
| 空状态“暂无库存快照” | 区分“没有符合条件”与“还没有库存” |
| 副标题“采购分批入库可追溯” | 新做：每行“流水”打开该商品在该仓库的库存流水（单号可点开原单据、滚动结存、累计入出库），新接口 `GET /finance/inventory-ledger`（需 finance.inventory.view，金额按成本权限脱敏，限本公司） |
| —（旧版无） | 新增：汇总卡（库存行数/商品种类/涉及仓库/缺货行数/库存成本合计）、平铺/按仓库/按商品分组小计、导出、刷新与数据时间、手机卡片 |
| 旧版数量合计无 | 合计行：多种单位时不相加（显示“—”） |

## 未完全结算收付款单、收付款结算明细表（旧版没有，保持行为）
筛选：日期（含快捷）、单据类型（原有）+ 关键词（本地筛，新增）；汇总卡、按往来对象/类型分组小计、合计行、导出、点单号看原单据、手机卡片。接口不变。

## 故意不做
- 旧版“库存快照/可用/占用/在途”：旧版接口只有已过账数量与金额，没有这些概念，新系统库存同样来自已过账单据，不虚构。
- 旧版现金银行直接显示账号明文：新规则要求明文需专门权限并留痕，所以保留按需显示。
- 聚水潭等外部系统：本页只读本地已过账数据，没有任何外部写入。
