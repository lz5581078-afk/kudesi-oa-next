# 直播下一场信息、排场产品与上次配置导入

## 范围

用户要求全览房间卡显示下一场时间、主播、中控、运营、产品；新增排场可选产品，并可一键导入上次排场。当前请求没有新的生产发布指令。

## 行为

- 全览保留南上北下布局；每张卡独立显示下一场开始/预计结束时间、三类人员及场次产品；中控和运营为空时显示未安排。正在直播也显示下一场，不再将 next 清空。
- 房间产品为房间基础设置；场次产品来自排场产品快照。正在直播的本场产品来自实际直播产品快照。旧排场产品为空时显示未选择，不把房间产品误当作场次产品。
- 新增、修改排场可搜索基础编码产品，多选最多 100 个，支持移除；保存时按当前公司校验产品启用状态，只存编码、名称、规格，不返回成本和价格。
- 报上播自动选中排场产品，仍可调整；上播既有店铺、产品、人员、时间校验继续有效。
- 新增排场先选择房间，再点一键导入上次排场。读取同公司同房间、所选开始时间之前最近一场未取消的排场；未填开始时间时取所选日期结束之前最近一场。
- 导入人员、抖音号、店铺、产品和备注；保持本次日期、开始和结束时间；显示来源日期时间，不自动保存。
- 没有历史记录时保持原表单；停用人员或账号清空并提示；失效产品在保存时拒绝并允许移除重选。切换房间、日期或开始时间后丢弃旧请求的返回结果。
- 新只读接口 GET /live/schedules/previous 同时执行 live.manage 路由权限和服务权限校验，令牌决定公司；房间引用必须属于当前公司。

## 结构

新增迁移 1763000000000-LiveScheduleProducts，只增加 live_schedules.products_json 可空 JSON 列，不修改原业务数据。注册于 MIGRATIONS。down 在已有产品快照时拒绝回退，避免丢失业务数据。

新增 ScheduleDialog.tsx 将原排场对话框独立；ProductPicker.tsx 负责搜索与多选。排场列表和房间当天详情同步显示产品和运营。
