# 直播管理布局重设计（全览页除外）

分支：`feat/live-ui-redesign`；基于 integration `97b1375`。仅前端 UI，无 API、权限、计薪公式或迁移改动；全览页面和原 live.css 未改。保留 main 上传统运营中控仅计提成的两项补充回归。

## 本轮界面证据与问题

用户提供的场次详情截图显示报告表格压缩、留白和内容不全。本轮通过 Codex 内置浏览器只读打开生产页面，进一步复现左侧导航压住弹窗左侧：弹窗 backdrop 实际 z-index=20，导航为30。全局 modal 样式、nowrap/ellipsis、flex 子项收缩及缺乏手机字段布局叠加，导致各入口体验不一致。未保存、提交或审批真实业务记录。

## 实现范围

- 排场、场次记录、待审核、主播工资、中控工资、运营提成、工资结算、人事补报、提成规则、通知设置共10个分区：统一页面标题、筛选、统计卡、结果列表/表格和操作层次。
- 手机用权限一致的页面选择器切换分区；全览仍沿用原有页面和导航布局。
- 详情、排场新建/修改、取消、上下播、审核/退回/拒绝、结算详情与嵌套场次、规则编辑/试算、试播主播：统一弹窗尺寸、标题/关闭、正文和底部操作，长表单错误固定在操作附近。
- 详情将时间、参与人、平台账号与店铺分区，报告和店铺业绩有明确标题。审核逐店对比可展开，工资和金额核定不再被长表格挤到不可发现的位置。
- 工资、结算、规则、报告、逐店业绩表在手机显示带字段名的卡片；店铺原因多行输入，订单选择有独立限高列表。
- 待办中的直播审核同样按金额/主播工资/中控工资分组，复用逐店表；产品和订单复选框显式保持横向排列。
- 场次列表和 CSV 展示全部直播平台/账号；所有核算和审批动作仍使用原 API。

## 验证

- Node 20：`npm run typecheck`、`npm test`、`npm run build`。
- 常规测试：shared 354、API 331、web 1080、agent 75，共1840项通过。API 的740项数据库测试按常规模式跳过；本轮没有业务后端或数据库变更，不据此声明全量数据库回归通过。
- 直播与待办专项55项（包含新增键盘焦点/最上层Escape、底栏错误位置和待办业务分组回归）通过，已包含在上述总数。
- 初次 Node 24 运行遇到既有 ResourcePage.leave 的 AbortSignal 与 jsdom 兼容错误；切换项目 CI 的 Node 20 后完整通过，没有修改无关资料模块。
- 内置浏览器以合成数据运行真实组件及应用外壳：1440×900 和390×844逐页检查10个分区；768×700另验审核弹窗。全部页面无横向溢出，手机响应式表格无缺失字段标签。
- 详情冷启动测量：1440×900弹窗位于(140,24)，尺寸1160×852；正文710px、内容1396px；报告表191px、店铺表482px均未压缩，backdrop层级1000且覆盖导航。
- 审核在768×700和390×844均无正文横溢出，底部按钮在视口内。测试空结果、读取失败、手填核定、订单展开、规则编辑、试播校验、嵌套关闭及未确认审核结果防重复提交。未绕过正常业务校验。
- 特别做刷新后的冷启动检查，避免热更新改变样式注入顺序掩盖全局样式冲突。
