# UI·兼职与临时工（资料 · 组织与人员 · 期限与计薪）

分支 feat/workforce。用户确认：旧系统资料导航里“兼职与临时工”（id workforce，说明“期限与计薪”，在“组织与人员”分组里、“人员档案”之后、“岗位档案”之前）新系统需要，完整补上。旧系统只作功能参考，不复制代码和视觉。

## 0. 旧系统怎么做（读过的源码）

来源（较新的一版，含该功能）：`server/modules/workforce/workforce.js`、迁移 0182（`employees.employment_type` + `employee_workforce_profiles`）、0185（`employee_workforce_attachments`）、0187（`live_wage_records`）、`src/resource-center/pages/WorkforcePage.jsx`、`schemas/workforce.jsx`、`schemas/workforce-attachments.jsx`、`schemas/employees.jsx`（人员档案过滤掉兼职/临时工）、`navigation-targets.js`、`server/index.js`（登录拦截）、`server/modules/live/{review,routes,access,wage}.js`、`docs/直播管理.md`。

旧模型：兼职/临时工就是 `employees` 的一行（`employment_type` = `part_time` / `temp`，所以登录、岗位、角色、任务派发、职责组原样可用），合作期、计薪、联系方式放在 `employee_workforce_profiles`，附件放 `employee_workforce_attachments`。整页只有公司管理员能进。

## 2. 设计取舍

- **为什么走通用资料框架 + 少量规则，而不是旧系统那样的专门模块**：列表/详情/表单/表格编辑/列筛选/导入导出/归档/到期提醒/权限/操作记录全部现成；兼职只需要配置 + 一份 `workforce-rules.ts`（建档校验、同步员工、停用交接）+ 读时派生字段。没有新表、没有迁移。
- **读时字段**：合作状态按“今天”实时算；账号、部门、岗位、上级、账号状态、最近登录取员工当前资料（不存进档案，所以员工调岗后不会过期）；只有搜索用的快照存进档案，且这些列在 `READ_TIME_FIELDS` 里不允许列筛选。
- **新增两种声明式条件**（shared `Cond`）：`future`（日期晚于今天，用于“待开始”）和 `viaUserNoPosition`（员工没有岗位，用于“没有岗位”）；服务端翻译成带公司条件的参数化 SQL。
- **停用交接抽成共用函数**：`apps/api/src/org/handover.ts` 从 `OrgAdminService` 原样抽出，`OrgAdminService` 只改成转调，行为不变。
- **登录拦截放在两处**：登录（密码正确后）和守卫（每次请求，仅非正式员工多查一次档案）。

## 3. 与旧系统口径不同的地方（原因）

1. 账号由系统生成随机初始密码（不让管理员手输）：CLAUDE.md 红线“没有默认密码”，且人员档案已是这样。
2. 没有档案的兼职/临时工**不拦登录**：防止上线当天把已有兼职锁在门外；改为醒目提示并可一键建档。
3. 人员档案不隐藏兼职/临时工：本页不能改岗位/重置密码，需要在人员档案里改。
4. “角色”：新系统用岗位承载权限，没有独立角色，所以无此字段。
5. 附件的大小/类型限制由通用文件服务统一（与旧系统的 8MB/12MB、JPG/PNG/WebP/PDF 口径一致，以文件服务配置为准）。

## 4. 迁移（旧库 legacy_full，只读空跑）

- 适配器：`scripts/migration/legacy-adapter.cjs` 新增 workforce 专项（来源编号 = 员工编号；用工类型、姓名、停用状态取自员工表；单价旧元→整数分，精度超范围整条不迁；附件按分类放进五个附件字段）；`mapping-rules.json` 新增 `workforce` 规则（表 `employee_workforce_profiles` + `employee_workforce_attachments`，备注 ← remark）；档案无公司列，经 员工→部门 确认公司归属（`employee_workforce_profiles` 已加入范围核实表）。
- 迁入只带资料：`workforce-rules` 在迁入事务里不改员工账号、不写薪资记录、不触发停用交接；员工已停用的档案也能迁成“已停用”。
- 适配器测试：`apps/api/src/migration/legacy-adapter-workforce.spec.ts`（假旧库，4 条）。
- 空跑（`import-legacy.js` 默认试跑、整个事务回滚；旧库 legacy_full 只读，目标是本机一次性新库）：旧公司 3，档案 **8 → 迁入 8**，失败 0、排除 0；附件 **0 → 0**（旧库附件表为空）；8 人旧库均为兼职、在职；单价均为 0（旧系统“还没定价”，新系统不拿它覆盖员工时薪）。迁入后需要在页面补单价。
- 没有对任何生产库做写入；`--apply` 未执行。

## 5. 上线后管理员要做的事

- 把 `resource.workforce.view / create / edit / status`（以及需要看/改计薪的人的 `org.staff.salary`）勾给需要的岗位——现有公司不会自动获得；新公司默认只有“老板”（`*`）有。
- 打开“资料 → 组织与人员 → 兼职与临时工”，看顶部“还没建档的兼职/临时工账号”提示，给他们补档案（合作开始日期、计薪）；补完才受合作期登录控制。
- 迁入的旧兼职如需按旧库档案补录：见迁入执行说明里 workforce 的对账。
