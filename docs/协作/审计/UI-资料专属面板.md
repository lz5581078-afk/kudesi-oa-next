## 6 店铺
- ✓ 筛选（领取状态/运营人/聚水潭/经营状态）、批量指派运营与领取状态、领退店记录子表、经营数据面板（StoreMetricsPanel）。
- ✓ 收回为公共店铺：带原因、清空运营人、写退店记录（StoreReleaseButton，CertPanels.test.tsx）。
- ≠ 指派运营：新系统用通用编辑/批量编辑改运营人，没有单独的“指派原因”弹窗和「指派后自动进入在运营」的专属提示。
- ✗ 快捷页签（在运营/历史负责人未指派/公共待领取/异常/已注销）：靠 filterBy 组合代替，未做一键页签（交 u1 的列表壳页签能力）。
- ✗ 领取规则折叠说明：已写在字段 help 里，≠ 形式不同。
- ✗ 领退店手工记录新增：通过子表通用新增可做（✓ 等价）。

## 6b 店铺快捷页签与指派原因弹窗（依赖 u1）
- 检查 origin/integration：通用列表壳只有 `tabsBy`（按字段值拆页签），没有“页签配置入口”（按筛选条件/计算条件定义的快捷页签）。
- 结论：「在运营 / 历史负责人未指派 / 公共待领取 / 异常 / 已注销」页签依赖 u1 的壳能力，我不改通用壳，记为依赖 u1。
- 「指派原因」弹窗：新系统指派走通用编辑/批量编辑改 operatorUserId，没有原因输入；做专属弹窗要在壳的批量动作里挂入口，同样依赖 u1，暂不做。（收回为公共店铺已做，带原因。）
