范围：旧系统的流程目录与设计器；新系统 `packages/shared/src/flow.ts`、`apps/api/src/flow/`、`apps/web/src/pages/flow/TemplatesPage`（流程配置）。
旧系统参考（只读，不复用代码）：`src/workflow/WorkflowDirectory.jsx`、`workflow-directory.mjs`、`WorkflowConfigurationCenter.jsx`、`WorkflowDesigner.jsx`、`NodeTemplateLibrary.jsx`、`InsertBusinessNode.jsx`、`WorkflowTimeoutSettings.jsx`；后端 `server/modules/workflows/`（template-maintenance、node-library、timeout-policy/routes/worker、designer-utils、node-timing）与旧表 `workflow_templates / workflow_template_nodes / workflow_node_library / workflow_timeout_*`。

## 0. 方案（先方案，后实现）

### 0.1 旧系统功能清单（流程目录与设计器）
1. **流程目录**（WorkflowDirectory）：左侧部门树（全部/全公司通用/各部门，带数量、可折叠），右侧列表：搜索（名称/部门）、业务类型筛选、启用状态筛选、分页 20 条；列：流程名称(#编号)、所属部门、业务类型、节点数、状态、配置检查（缺办理人等问题）、操作（配置/复制/停用/删除）。
2. **新建/复制流程**：名称 + 业务基础（SKU/采购/专属品/直播/空白）；复制保留全部节点与配置，名称默认“XX副本”。
3. **停用/删除**：停用保留历史、停止发起；删除只允许从未被使用过的流程（有申请或历史就只能停用），删除前确认，写审计。
4. **流程详情四步**：①业务模板与处理人 ②流转与退回 ③检查与启用 ④超时与处罚；顶部复制/停用/删除；有未保存修改时离开要确认。
5. **可视化设计器**（WorkflowDesigner）：节点列表/画布两种视图；节点类型 12 种；节点属性：名称、编号、分支标识、处理方式（单人/任一/全部/按条件）、处理对象（人员/岗位/角色/职责组/发起人上级/关联资料负责人/上一节点处理人/部门全员）、处理时限、是否生成待办、是否需要复核、提交内容（字段）、字段权限（可见/可改）、自动动作（生成业务记录/财务流水/冲抵预付款/更新资料状态…）；连线：下一步、退回线、异常线、汇合等待；右键菜单（新增/复制/删除节点、设为发起/结束、配置连线）；校验流程、保存；“业务条件流转”（按条件走不同下一步，旧系统只给采购用）。
6. **节点模板与节点默认页面**（NodeTemplateLibrary）：节点中心按分类列出业务模板（48 个），可复制新建/编辑（名称、用途、默认处理人来源、是否生成待办、字段可见/可填写），修改模板不影响已配置流程（存修订号）。
7. **督促时效**：每个节点可开“督促助手时效提醒”：到期前两次提前提醒、超时后按间隔重复提醒；采购节点另有按承诺发货日/预计到货日督促；节点抄送人员；超时升级（超过 N 分钟通知指定人员，可加多条）。
8. **超时规则与处罚台账**：公司默认 / 流程独立 / 节点独立三级规则（后者覆盖前者）；通知规则（主管 N 分钟、老板 M 分钟，接收人自动或指定员工）；处罚规则（固定/累计/分档，封顶，按任务/节点计次）；台账列表（超时事件、通知送达状态、处罚计算金额）、对处罚确认或免除（必须写原因、金额不得超过计算值、留痕）。处罚只对“有明确个人办理人”的节点计算（共享部门收件箱不处罚）。规则修改带版本号（并发冲突提示）并留痕。
9. **启用与版本**：检查通过才能启用（缺办理人则指出哪个节点）；启用后新申请按新配置，在办的不变。

旧系统死代码/不进范围：旧“采购样板生成”“直播场次审核/直播月结流程”（直播整页新系统没有，归别组）；`InsertBusinessNode` 的采购专用节点插入（采购流程归 u10，业务节点在内置采购模板里固定）；画布里自由拖拽的像素级布局（新系统用自动排布）。

### 0.2 新系统数据模型（向后兼容，只加不删）
| 对象 | 存放 | 说明 |
|---|---|---|
| 内置模板 | `packages/shared/src/flow.ts`（不变） | 借用执照/费用申请/专属品/SKU 批量申请。业务适配器、locked 步骤、自动记账声明都不变 |
| 公司自建模板 | 新表 `flow_templates`（公司、key、名称、说明、所属部门、创建人） | 只存“身份与目录属性”。key 形如 `c1a2b3c4`，不会和内置 key 冲突 |
| 模板版本 | 现有 `flow_definitions` + 新列 `schema_json` | 一个版本 = 步骤配置（steps）+ 表单结构（发起字段 fields、各步办理字段 stepFields、自动记账声明 posting，仅自建模板用 schema_json）。已发布版本不可改，改就出新版本 |
| 在途流程 | `flow_runs.definition_id` + 既有 `steps_snapshot` | 自建模板的表单结构跟着 definition 版本走，旧版本行永不删除，所以修改模板不影响在途流程；内置模板不变 |
| 节点模板 | 新表 `flow_node_templates`（公司级）+ 代码里的内置节点目录 | 节点模板 = 名称、步骤类型、默认时限、默认页面（该步办理时要填的字段）、默认办理人来源；套用时复制进步骤，之后互不影响（等价于旧系统“修改模板不影响已配置流程”） |
| 超时与处罚 | 新表 `flow_timeout_policies / flow_timeout_incidents / flow_timeout_penalties / flow_timeout_events / flow_reminder_logs` | 金额一律整数分；规则带 revision；事件表留痕 |

迁移号段 1746…：`1746000000000` 自建模板与节点模板（`flow_templates`、`flow_node_templates`、`flow_definitions.schema_json`）；`1746000001000` 超时与处罚、督促提醒记录。都只加表加列。

### 0.3 与统一流程引擎的兼容
- 引擎仍是线性步骤 + 待办 + 事件。新增能力都是 StepDef 上**可选**的声明字段，没有声明的旧流程行为完全不变：
  - `when`（条件分支）：进入该步前按发起表单/已办步骤表单里的值判断，不满足就记一条“已跳过”并走下一步，结束步不可跳；这样“金额<1000 主管审、≥1000 再加老板审”用两个带相反条件的审批步骤表达，办理人仍由统一配置解析。
  - `returnToKey`（退回到指定节点，对应旧 reject 连线）：默认退回上一个会执行的步骤。
  - `mode: 'all'`（部门全员会签，对应旧“多人全部处理”）：部门步骤全部人办理完才流转；默认仍是任一人办理。
  - `remind`（督促时效）：到期前 N 分钟、超时后每隔 M 分钟提醒，由现有每分钟扫描器执行，`flow_reminder_logs` 唯一键保证每条只发一次。
  - `hiddenFields`（字段权限）：该步办理人看不到的发起字段（如仓库看不到金额），服务端在详情接口里过滤，不是前端隐藏。
  - 办理人来源新增 `requester_manager`（发起人的上级）、`previous_handler`（上一步办理人）。
- 自建模板走同一个 `FlowService`：`tpl()` 改成按公司和版本解析（内置优先，自建模板从 definition 读 schema），适配器没有的 key 用通用适配器（标题取模板名+首个文本字段，没有业务副作用）；自动记账声明沿用 `posting`，仍由 `validatePostingDecl` 校验。**不在业务模块里写死审批人**：所有办理人、顺序、条件都在流程定义里。
- 内置业务模板（借用执照、费用申请、专属品、SKU 批量申请）：步骤 locked 规则不变，管理员依旧只能改办理人/时限/抄送和增删非 locked 的审批步骤；新增的条件/督促/字段权限等对它们也可用于非 locked 步骤，locked 步骤只允许配督促时效和抄送。已有测试全部保留并通过。
- 发布规则：每个办理步骤的办理人必须当下解析得到人（沿用）；自建模板还要检查表单结构（字段键唯一、类型合法、条件引用的字段存在、记账声明合法）。
- 版本与启用：保存=草稿；发布=新版本启用，旧启用版本变“已停用(retired)”；**停用**=把当前启用版本退役（不能再发起，在办的不受影响）；**启用某历史版本**=回退。删除：自建模板且从未发起过才允许（连同草稿/版本一起删）；内置模板不能删，只能停用。复制：复制步骤与表单结构成一个新自建模板（复制内置模板得到一个可自由改的自建模板，业务适配器不会复制）。

### 0.4 页面与权限
- `/flow/templates`（流程配置，既有页面改版）：流程目录（部门树+搜索+筛选+列表+配置检查+复制/停用/删除/新建）→ 点进去是流程详情（设计器）。
- `/flow/node-templates`（节点中心，新页面）：分类 + 搜索 + 模板列表 + 详情编辑，复制新建。权限键 `flow.node-templates.view`；编辑要 `flow.templates.manage`。
- `/flow/timeouts`（超时与处罚，新页面）：公司默认规则、流程独立规则、台账与处罚确认。权限键 `flow.timeouts.view`；改规则要 `flow.templates.manage`；确认/免除处罚要新权限 `flow.penalties.manage`（涉及钱，单独授权）。
- 流程总览页头增加“流程配置/超时与处罚”入口（有权限才显示）。
