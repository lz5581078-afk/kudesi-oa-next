# 直播本场有效订单营业额

## 用户口径

重新设计全览房间卡的本场区域，加入聚水潭营业额，点击按店铺显示有效订单数和金额。先按本场成单时间确定订单，再核算有效金额；以前成单但本场退款的订单完全不参与本场统计。

## 实现

- 独立只读 GET /live/sessions/:id/turnover；显式声明登录要求，服务层 loadLiveAccess/requireView 检查直播管理查看或管理权限。场次查询强制令牌公司，客户端不能提交店铺或时间范围。
- 来源新增 turnoverOrders，不复用报下播的付款时间候选，也不改变原报下播、审核、工资、提成、结算口径。
- 聚水潭订单查询 date_type=2、普通订单类型；再次验证店铺和 order_date。时间窗为实际开播（包含）到实际下播（不含），直播中截止本次查询开始时间；相邻场次不重复计边界订单。下播后固定成单窗口，售后状态可随后续刷新更新。
- 实付优先 paid_amount，缺失时只加总 pays/pay 中 is_order_pay=true 的订单支付；不使用应付 pay_amount 冒充实付。未付款、取消不计，补发换货不混入普通销售。
- 只对筛入本场的订单ID调用既有退款核对，历史订单即使本场有退款也不请求、不扣减。已确认退款按原订单金额封顶；部分退款保留剩余金额，全退不计有效单数。
- 同公司同聚水潭店铺去重，多账号不会重复加总。按店铺返回有效单数、实付、已确认退款、有效营业额及合计；任一店铺不可确认时总额为 null，不把漏查当零。成功店铺明细仍可查看。
- 未绑定、未授权、缺少成单时间/金额、分页失败、拆合单或重复编号等情况明确不可用，不发布不完整总额。单次最多200页，超出拒绝；超过48小时的异常直播窗也拒绝。
- 缓存按公司、场次、起止时间、状态和店铺快照隔离，合并并发查询。成功缓存30秒，失败10秒，最多200项；每次缓存读取仍先鉴权。每批最多并发查询3店。
- 房间卡展示紧凑三角色、营业额按钮、开播/下播/预计下播、已播和进度；结束后保留所选日最近一场。约30秒自动刷新，页面隐藏时暂停刷新。
- 弹窗桌面为表格，手机为店铺分块；保留统计窗口、各店单数与金额、退款、合计和更新时间。异常不显示零，无原始订单或买家资料返回前端。
- 无新增数据库迁移，无外部写入，无新权限键。

## 来源核实

聚水潭官方[订单查询文档](https://openweb.jushuitan.com/dev-doc?docId=22&docType=4)：date_type=2 对应 order_date，实付字段与应付字段不同，支付节点须区分订单支付。按该定义实现成单归属及实付口径。
