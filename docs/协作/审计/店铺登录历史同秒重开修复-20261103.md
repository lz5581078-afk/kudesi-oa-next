# 旧登录浏览器历史同秒重开

源PR310第三轮完整CI的浏览器创建返回500，后续截图用例缺少浏览器是连带失败。前两轮源检查和正式main发布检查曾通过，不能用再次重跑掩盖。

已在隔离MySQL使用合成会话回滚事务确定性复现：不同UUID、同一device/profile、同一秒的两条closed历史触发`ER_DUP_ENTRY`，唯一索引为`uk_managed_browser_device_profile_opened`。旧DDL的opened_at为秒精度TIMESTAMP，索引不区分已关闭历史，实际核心使用CURRENT_TIMESTAMP创建，因此快速关闭后重开也可能失败。

1777000000000已部署，不改历史迁移。新增1778000000000仅将错误唯一索引改为同列普通检索索引，保留UUID主键、全部行、原业务事务/行锁和活跃浏览器保护。down发现同秒历史会拒绝恢复旧索引，不删数据。独立数据库回归固定同一秒验证修复前拒绝、修复后保留历史并成功重开、主键仍唯一、重复历史拒绝回退及无重复时可恢复。

只涉及兼容表结构；native默认行为、源码快照和0.3.45安装包均不变。线上旧引擎已核验未启用，现有native路径不受此兼容修正影响。

本地类型及构建通过，独立隔离MySQL共12套77项通过；其中真实HTTP并发登记同一个请求/电脑/Profile，两个201返回相同浏览器ID，数据库仅1条open行。独立审查确认原request/binding行锁及绑定唯一键保留，互斥不依赖错误的时间索引。尚未把这项修正宣称已上线，以后续发布核验为准。
