# 开播时间偏差通知

用户要求：实际开播相对排班开始时间提前或推迟超过5分钟时，通知人事部门和总经办部门。本次仅开发，不部署、不发送真实测试通知。

在上播成功的同一数据库事务中，比较场次记录的实际start_at和关联排场start_at，绝对偏差严格大于300秒才通知，正好5分钟不通知。手工选择实际开播时间时以该时间比较，不以点击上报时间比较；无排班场次无基准，不误报。消息含房间、场次号、主播/中控/运营、完整计划/实际时间、提前或推迟的分钟秒数。

收件人为同公司启用的人事部/人事综合部/人力资源部、总经办/总经办部门/总经理办公室及启用子部门的在职员工，主部门、有效主岗/兼岗均可识别，按员工去重。停用部门不作为子部门展开桥梁，停用岗位、停用员工和其他公司不收。沿用直播通知开关、站内通知和飞书事务出站及绑定/通道开关，不调用外部发送器进行测试、不强行开启现有开关。

同场次同收件人唯一事件键，重复上报不重复提醒；上播回滚同时撤销通知/队列。飞书真正发送前再次校验开关、场次偏差及当前部门成员资格，调离或停用的员工不接收积压信息。无表结构、权限、UI或迁移变更。

类型检查及API构建通过；常规shared354/API331/web1075/agent75全部通过；独立隔离MySQL173套1073项全部通过。新增真实上播入口和通知数据库测试覆盖实际时间与登记时间不同、两边正好5分钟/5分1秒、两部门与子部门、兼岗去重、跨公司/停用人员、无排班、重复上报、事务回滚、飞书事务入队、关停及调离后的发送前校验。

初次并行运行整套前后端与数据库检查时，既有远程协助测试超过5秒并引起后续假时钟测试连带失败；新增通知测试的多场直播中夹具也触发现有同房间唯一约束。已修正夹具为已下播历史场次，真实开播由独立入口测试覆盖。串行重跑完整数据库检查通过，本地为繁忙环境使用20秒单测上限，无产品超时规则或CI配置改动。无生产连接、未发送真实通知。
