# 公司店铺维护与店铺提现对照完善

分支：`feat/store-maintenance-parity`。对照来源为用户指定的 `test.kudesi.com` 实际登录页面，以及交接包内 2026-10-24 的 `src/session-manager/` 源码。旧源码只作行为和界面参考；实现仍使用新系统的 React、NestJS、MySQL 8。

## 实现范围

- 公司店铺维护与财务店铺提现共用一套页面组件，分别调用自己的接口及权限。还原标题区、在线电脑状态、登录状态/授权电脑/操作日志、搜索筛选排序、每页 10–200 条、固定操作列和批量添加窗口。
- 维护使用主账号、主账号密码；提现使用提现运营账号、提现运营密码。行内合并保存，空密码不覆盖旧密码；轮询不覆盖正在编辑的内容。查看密码另行鉴权并记审计。
- 维护可修改正常、异常、注销、停用；异常必须选同公司有效且未归档的原因。状态、原因和变更审计在同一个事务中保存，失败全部回滚。
- 候选店铺支持平台、运营、名称、编码、平台 ID 搜索，不再截断到前 100/500 条；排除已加入及归档档案。每次添加上限 100 家，需要指定有效授权电脑。
- 授权电脑支持备注、绑定、撤销/恢复、删除已撤销记录、版本发布、下载、单台及批量升级。沿用新系统公司级共用的电脑授权；两种用途的店铺清单、凭据、远程会话和新增店铺日志分别隔离。
- 维护远程协助新增独立权限 `resource.company-store-maintenance.remote`；服务端检查工作区，另一工作区不能读取、结束或延长会话。远程配置和紧急停止仍按公司内授权电脑生效。
- 助手 1.1.1 按服务器来源、公司、用途和店铺建立独立环境；打开、远程协助、提现截图都核对环境标识。维护任务拒绝旧助手，已排队任务遇到降级会安全失败，不下发维护凭据。
- 助手回传白名单阶段和百分比，页面展示实际进度；终态不能退回进行中，错误文字清除密码。
- 提现保留既有提现记录、提现单、收款账户、凭证上传/截图和记账引擎；详情中的“登记提现”会预填店铺。没有新增真实付款或自动提现动作。
- 从同公司已发布且校验通过的升级包生成 Windows ZIP 安装包，浏览器再次检查 SHA-256。修复中文路径下打包复制崩溃，并给中文 PowerShell 脚本加入 UTF-8 BOM，兼容 Windows PowerShell 5.1。

## 数据库与发布

新增结构迁移 `1758000000000-SessionMaintenanceParity`：电脑备注、审计工作区及索引、登录请求进度字段。迁移已在隔离开发库和测试库执行；未修改已执行迁移，未开启 synchronize。

Docker API 镜像增加 Windows 安装模板目录。助手需发布本次生成的 `apps/agent/release/update/kudesi-assistant-1.1.1.kapkg` 后再安排升级，安装包和编译输出不进 Git。新环境首次使用可能需要重新登录，既有本机 Profile 文件不会被本次服务端迁移删除，也不会自动复制到另一用途。

正式站代码已只读核对并拉取，未写生产数据库，未部署或合并 main。正式部署前按 AGENTS.md 检查任务板并备份 main；应用部署后需发布助手、升级负责电脑并完成一次实际联机验收。
