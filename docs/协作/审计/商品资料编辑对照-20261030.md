## 服务端补齐

- 分类名称按档案类型和上级目录判重；分类码按类型隔离。导入遇到同名不同路径时明确报错，支持完整路径定位。
- 分类目录及数量排除归档记录；分类存在子项或使用记录时，继续执行原有删除/层级校验。
- 同级排序由一个事务完成，任一失败整体回滚；跨公司、跨父级、跨类型的排序拒绝。
- 顶级档案标识保存在 JSON 资料资源，影响后续自动编号，已有商品编码不改写。无表结构迁移。
- 基础编码专属资料与组合资料使用白名单动作，身份只取令牌，沿用资料校验和审计。启停仍需对应权限和原因。
- 商品编码预览补齐包装/尺寸字段，允许具有编辑权限的人员使用；手工编号时也返回基础信息全名。

## 保留的明确业务规则

1. 用户已确认的报价精度保留：元最多六位小数，使用定点金额计算；结算仍为整数分。
2. 原料名称规格与采购系统规格分开，按系统规格计采购重量；人工不计物理重量，损耗只计成本。没有恢复旧版已修复的 SKU 问题。
3. 已生效引用的基础编码继续锁定身份、分类和重量；改名会按现有规则触发重验证。组合停用再启用恢复待验证，不能冒充已审核。
4. 费用单是否必须挂对象按挂账节点计算，界面只读；新系统已有额外资料放在补充/更多设置中，不丢字段。
5. 分类顶级编号采用明确保存动作，避免修改编号时静默改写既有档案。
