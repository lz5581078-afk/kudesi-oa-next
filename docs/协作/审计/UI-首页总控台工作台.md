# UI 整页新建审计：功能首页、老板总控台、角色（岗位）工作台、个人任务面板（u7）

范围：旧系统有而新系统没有的四个整页。只作功能参考，没有复制旧代码、类名或样式。状态：✓已有/已补　✗缺失　≠不同。
旧系统来源：`src/features/FeatureHome.jsx`、`src/dashboard/OperationalPages.jsx`（BossDashboard）、`src/workspaces/`（RoleWorkspaces、PersonalTaskPanel、OperationsWorkspace、workspace-catalog/access）、旧后端 `server/index.js` 的 `/api/dashboard/:role`、`/api/supervision`、`server/modules/workspaces/personal.js`。
新系统页面：`apps/web/src/pages/workspace/`；接口 `apps/api/src/workspace/`；共享定义 `packages/shared/src/workspace.ts`；菜单在“工作台”分区下新增 4 页（功能首页、老板总控台、岗位工作台、个人工作台），权限键 `workbench.home|boss|desk|personal.view`。

## 一、旧功能清单与新实现方案

| 旧页 | 旧功能 | 新实现方案 |
|---|---|---|
| 功能首页 | 按权限列全部菜单入口；搜索（多关键词）；最近使用（6 条，本机记忆）；按模块分组，手机默认折叠；无权限引导 | `HomePage`：入口全部来自导航注册表 `visibleSections(can)`（不另设权限），搜索复用 `searchNav`，最近使用存 localStorage |
| 老板总控台 | “需要你处理”4 卡（开放异常/超时任务/异常店铺/资质手机号提醒）；今日销售额/利润；全公司异常列表；人员兜底排行；店铺利润 7 天排行；利润趋势；数据截至时间+刷新 | `GET /workspace/boss`（`workbench.boss.view`）：待办/流程超时、异常店铺、资料到期（复用 `ResourcesService.expiring`）、店铺经营数据汇总；异常与售后/直播走“接口位”，没有模块标“暂无该模块” |
| 角色工作台 | 一个岗位一个工作台、按部门分组；岗位模板 31 种→新系统 `positions.workspace_type` 9 种（显式字段）；今日待办 4 卡；常用业务入口（按权限过滤）；流程与待办（待我处理/我的申请/已办结，搜索+分页）；发起申请列表；待接入业务提示；运营每日经营（日期、营业额/推广费/利润/利润率、部分店铺未更新提醒）、常用工具（定价调试） | `GET /workspace/catalog`（岗位目录，按部门路径分组；有“部门与岗位”查看权限或管理员可浏览全部，其他人只看本人在岗岗位）；`GET /workspace/desk/:positionId`（岗位汇总卡片）；入口由 `DESK_DEFS[workspaceType]` 引用导航页面键；流程/待办复用流程引擎已有接口；运营加 `GET /workspace/daily` |
| 个人任务面板 | 四分类：新任务/进行中/待我复核/已完成，带数量；任务详情（状态、执行人、截止、完成标准、结果）；到任务中心办理 | `GET /workspace/tasks?view=`；新增迁移 1747000000000 给待办表加 `started_at/submitted_at/review_note`；动作：开始处理、完成（沿用任务中心接口）、提交复核、复核通过/退回；提交复核后不能直接完成 |

旧系统里依赖别的小组新建模块的部分（兜底监督异常、售后、直播汇总）：做成 `WorkspaceModuleRegistry` 接口位，见第五节。

## 二、逐页对照

### 1. 功能首页 `pages/workspace/HomePage.tsx` ← `features/FeatureHome.jsx`
①布局：旧＝页头 → 搜索框 → 最近使用 → 按模块折叠分组的入口卡片。新＝同样顺序。
②功能
- ✓ 全部入口按权限列出、功能首页自身不在列表（`功能首页 > 按权限列出功能…`）
- ✓ 搜索多关键词、显示“找到 N 个功能”、无结果引导+清除（同上）
- ✓ 最近使用 6 条，点开即记录，刷新后还在（`点开的功能进“最近使用”，并记在本机`）
- ✓ 模块分组带数量；手机宽度默认折叠（`ws-fold` + matchMedia）
- ✓ 没有任何功能时引导联系管理员（`一个功能都没有时给出引导`）
- ≠ 旧入口卡片带一句 description；新导航注册表没有描述字段，卡片副标题显示“分区·分组”（不为此改共用导航结构）
③保留的优化：最近使用、搜索占位提示总数（✓）。

### 2. 老板总控台 `pages/workspace/BossPage.tsx` ← `dashboard/OperationalPages.jsx` BossDashboard
①布局：旧＝页头+数据截至+刷新 → 需要你处理 → 今日经营 → （全公司异常 | 人员兜底排行）→（店铺利润排行 | 利润趋势）。新＝同样。
②功能
- ✓ “需要你处理”卡：开放异常（监督接入后）、已超时待办、超时流程、异常店铺、资料到期提醒（已过期/30 天内），数字可点进对应页面（`先显示需要处理的事…`）
- ✓ 今日销售额/利润；无数据时说明“今日暂无店铺经营数据”；利润含采购成本，**没有 product.cost.view 的人服务端不返回**（`没有成本权限时利润显示“—”…`；API `noCost`）
- ✓ 全公司异常（最紧急 8 条，紧急/重要/一般标签，升级层级）：监督模块接入后显示；否则“暂无该模块”
- ✓ 人员兜底排行（超时多的在前，含待办数；异常数由监督模块提供）
- ✓ 店铺利润排行（近 7 天，合计，按利润排）、经营趋势（近 14 天柱图）
- ✓ 数据截至时间、手动刷新、页面可见时每分钟自动刷新、失败重试
- ≠ 旧“资质/手机号提醒”拆两类；新系统用统一到期提醒，卡片提示“已过期 N · 30 天内到期 N”
- ≠ 旧利润趋势取财务汇总；新取店铺经营数据日汇总（财务明细有链接，避免重复口径）
③保留：全部卡片可点；0 数据不显示误导性的 0（缺模块显示“—”）。

### 3. 岗位工作台 `pages/workspace/DeskPage.tsx`、`RoleDesk.tsx`、`FlowSection.tsx` ← `workspaces/RoleWorkspaces.jsx`、`OperationsWorkspace.jsx`、`workspace-access.mjs`
①布局：旧＝导航里“我的 + 每个部门一组、一个岗位一个入口”；页内 页头 → 今日待办概览 → 常用业务 → （流程与待办 | 个人任务+发起申请）。新＝顶部岗位选择（按部门分组的下拉，标“我的主岗位/我的岗位”）→ 页头 → 概览卡 → 岗位专属区块（运营：每日经营）→ 常用业务 → （流程与待办 | 个人任务）。
②功能
- ✓ 一个岗位一个工作台、按部门路径分组；默认进本人主岗位；管理员/有岗位查看权限的人可浏览全部，其他人只看在岗岗位（`岗位目录…`、`按部门分组选岗位…`）
- ✓ 岗位类型来自 `positions.workspace_type`，不按名称猜（`DESK_DEFS` 覆盖全部 9 种，共享测试校验入口都是真实导航页）
- ✓ 今日待办概览：待我处理/已超时/我的申请，点击进对应页；岗位卡片（财务草稿/已开立未过账、资料已过期/将到期）
- ✓ 常用业务：只显示有权限且页面已完成的入口；主管级岗位（positions.level）多出管理入口（`常用业务只显示有权限的页面`）
- ✓ 流程与待办：待我处理/我的申请/已办结三页签，搜索（走服务端）、分页、逾期标红“已超时”、被退回标记、空状态、失败重试（`流程列表：逾期行…`）
- ✓ 运营每日经营：选日期（默认昨天，前后一天）、营业额/推广费/利润/利润率（整数百万分比换算）、“N 家店铺当天没有数据”提示；无成本权限不返回利润（`每日经营…`；API `每日经营…`）
- ✓ 运营常用工具：定价调试表入口
- ✓ 待接入业务提示（仓库收发货汇总、采购到货汇总，旧系统也标“未接入”）
- ✓ 依赖模块（售后/监督/直播）没有时卡片显示“暂无该模块”（`缺模块的卡片显示“—”`）
- ✓ 没有岗位时引导（`没有岗位时给引导`）
- ≠ 旧“发起申请”侧栏列模板并弹窗发起；新系统统一到“申请中心”（页脚链接），不在工作台里复制发起表单
- ≠ 旧运营账号“固定工作台、不可浏览别的”规则（按名称/账号判断）不保留；新系统只按权限+岗位目录可见性
- ✗ 旧运营工作台里的直播摘要/报上下播、采购申请中心、专属品申请、仓库退回规格：属直播（u9）/采购与 SKU 批量（别的任务），本页留 `live` 接口位，对方接入后自动出现
③保留：搜索防抖、超时置顶标红、空状态文案“暂无待我处理的事项，歇一会儿”。

### 4. 个人工作台 / 个人任务 `PersonalPage.tsx`、`PersonalTaskPanel.tsx` ← `workspaces/PersonalTaskPanel.jsx`、`personal.js`
①布局：旧＝个人任务面板（四分类页签+列表+分页+详情弹窗）嵌在每个工作台右侧。新＝同样嵌在每个工作台；“个人工作台”是不绑岗位的同一页面。
②功能
- ✓ 四分类带数量：新任务/进行中/待我复核/已完成（`四个分类都带数量`）；新任务＝我负责且未开始，进行中＝已开始或已提交等复核，待我复核＝我指派、对方已提交，已完成＝我负责已结束
- ✓ 行内：标题、指派人、截止与“还剩/已超时”、状态标签；超时红色
- ✓ 详情：状态、负责人、指派人、截止、开始/提交时间、说明、处理说明、复核意见
- ✓ 动作：开始处理、完成（带说明）、提交复核（带说明，只有别人指派的任务可以）、复核通过、退回（必须写原因）；每步通知对方（`新任务：开始处理…`、`提交复核带说明…`；API `个人任务四分类…`）
- ✓ 提交复核后负责人不能直接完成（任务中心接口也拦截），退回后回到“进行中”并显示复核意见
- ✓ 刷新、失败重试、空状态、分页、操作成功提示
- ≠ 旧任务有“异常/已退回/监督人/完成标准”等多状态；新系统任务表只有 open/done/cancelled，本轮用“开始/提交/复核”三个时间列表达四分类，不引入异常/延期（延期申请等在 u5 审计里记为需用户确认）
③保留：待复核按指派人看、逾期优先排序。

## 三、权限与默认可见
新权限键 `workbench.home|boss|desk|personal.view` 自动进入权限目录；新建公司的默认岗位已含首页/岗位工作台/个人工作台；老板岗位 `*` 含总控台。**已部署公司的现有岗位不会自动获得新键**（权限数据不由迁移写入），需管理员在“部门与岗位”里勾选，公司管理员本来就全部可见。接口：个人任务/目录/动作只要登录（只看本人数据），`desk`/`daily`/`boss` 按权限键拒绝；公司和本人只取令牌；数据全部带 company_id。

## 四、迁移
`1747000000000-TaskReviewStages`：`work_items` 加 `started_at`、`submitted_at`、`review_note`（可空，向后兼容，已登记任务板）。

## 五、给 u8（售后）/u9（监督、直播）的接入说明
`apps/api/src/workspace/module-registry.ts` 的 `WorkspaceModuleRegistry`（已在 AppModule 提供）：对方模块在构造函数注入它并 `register({ key: 'supervision'|'after-sales'|'live', ... })`：
- `supervision.exceptions(user)` → `{ total, rows: BossException[], byUser }`：总控台“开放异常”卡、全公司异常列表、人员排行异常数；
- `bossCards(user)`：总控台“需要你处理”追加该模块的卡片（售后待处理、直播异常…）；
- `deskCards(user, workspaceType)`：岗位工作台追加该模块卡片（客服/仓库看售后，运营看直播）。
没有注册时页面显示“暂无该模块”。卡片的 `page` 填导航页面键（如 `after-sales.tickets`），页面 ready 且有权限才可点。接入测试样例见 `workspace.db.spec.ts`。
