# 资料迁入：范围、单位与执行边界

本次用户授权将指定旧公司的资料、财务基础资料及登录账号迁入新系统，并明确选择保留原单价精度。旧库只读。新生产库写入属于这次授权范围；本工具不自动执行、不挂启动钩子、不提供 HTTP 导入入口。

## 不改变结算金额口径

单位报价和单位成本支持元小数点后六位（JSON 仍以分为基数，最多四位小数），使用 shared/unit-price 的十进制定点运算。采购、人工、包材、运费报价与构成汇总不先舍入到整分；单据行在数量乘单价之后结算到分，分录、收付款、预收预付和余额仍为整数分。最低售价最后向上取整到分。

单据单价/单位成本和成本快照的单位成本列用 DECIMAL(24,4)，不是把所有金额列改成小数。前端录入、资料 CSV 导入导出、成本显示与单据明细同步支持精细单价。用户确认记录优先于早期“旧密码不能迁”“单价一律整数分”的评估说明。

## 账号和资料转换

- 原员工盐和 scrypt 哈希按明确版本编码保存，原密码首次成功登录时原子升级 bcrypt；并发重置密码会拒绝旧凭据登录。原停用人员保持停用；当前底薪按原值精确换算为整数分并沿用新薪资权限，旧计薪制度/薪酬历史不混入账号字段；无账号人员以 NULL 账号保留，不能登录，不生成默认密码。
- 旧明确管理员角色 admin/company_admin/boss 对应本公司管理员，不对应平台管理员；普通员工按明确的新旧权限对应转换，未知菜单/外部同步权限不扩大授权。保留已有目标管理员。
- 资料走与手工录入相同的字段、引用、唯一、加密、文件校验。迁移事务允许保留旧停用人员引用和未验证组合构成，避免虚构人员/关联；迁入编码先待核对，不能直接作为新系统已验证资料对外发布。
- 马甲沿真实编码追溯原料，保留旧编码、名称及组合引用。抑制导入时自动生成重复马甲/证照关联资料。原马甲名和规格没变时，普通成本编辑不会重命名马甲。
- 供货来源保留原更新时间及排序依据，全部入库后统一计算当前来源及成本，避免导入顺序改变当前采购价。不会按旧缓存值覆盖新公式。
- 同一物理手机号/银行账号和相同主体信用代码的重复来源可在校验身份后归为一个新对象；所有旧 ID 保留对应，字段冲突不覆盖、逐项报告。无对应的新必填字段不填假值。已删除但仍被当前费用项目引用的分类只按停用分类保留关系，不复活为可用分类。
- 原单据、审批、运行日志、Cookie/设备令牌、外部接口授权不迁。账户/店铺余额不自动变成期初分录。旧命名规则使用另一套分类范围，不直接激活；现有组合通过受控手工保留字段保存原码原名。

## 运行和对账

源码适配器 `scripts/migration/legacy-adapter.cjs` 只在服务器读取原应用已有配置；密码、密钥和业务值在内存中转换，实际数据不进 Git。它只读取指定公司或已核实公司归属的父记录链。排除的历史/运行类数据只取来源 ID，不读整份载荷。

编译后的 `apps/api/dist/scripts/import-legacy.js` 默认试跑，整个事务回滚。`--apply` 必须同时提供源/目标公司、目标库确认文本和已核对报告；源资料指纹、非文件行数量或失败清单改变会整批回滚。报告在提交前先写 prepared 状态，提交后标 apply。单条记录失败会回滚该行和联动，报告每个未写字段/行，不能把失败条目数简单加成唯一业务记录数。

```sh
node apps/api/dist/scripts/import-legacy.js \
  --source-company <旧公司ID> --company <目标公司ID> --actor <目标管理员ID> \
  --expected-name <核对过的目标公司名> --adapter <服务器适配器绝对路径> \
  --report <私有目录/唯一报告名.json>
```

隔离试迁用新库副本与独立文件目录。核对后再加 `--apply --confirm <库名:目标公司ID:旧公司ID> --expected-report <已核对报告>`。正式导入前还必须检查当前目标数据，做备份并验证可读；保留 source hash、旧新 ID、数量、金额差异和附件摘要。报告和实际业务清单只在私有目录。

`scripts/migration/verify-import.cjs` 独立只读对账：原账号/状态/密码哈希、细单价、引用、原编码/马甲名、敏感字段在内存解密比对、附件尺寸及 SHA256；报告不写出密码或卡号。失败项、重复资料差异和排除项附旧新 ID，供私下核对。

复跑只复用已迁入对象，不覆盖新系统中人的修改；源资料/转换协议变化会停止，须重新评估，不能清空账本强行重跑。按同一已验证代码版本和源快照复现。每次报告用新文件名，避免覆盖前次证据。

## 私有文件与发布

没有七牛配置时可使用服务器私有存储：配置 `FILES_LOCAL_ROOT=/data/files`，并把私有持久目录挂载到该路径；生产目录应由 API UID 1000 持有，文件 600、目录 700。本地对象带 local: 存储标识，后续配置七牛也能继续访问原文件。文件 URL 先检查公司和资料权限，再签发最多五分钟的路径绑定链接，响应禁止缓存；不公开旧上传目录。

新版本和结构迁移必须先通过测试和备份发布，再运行数据 CLI。应用发布只备份程序与数据库；正式导入另行保存文件目录备份。回退程序不会逆转已导入数据，恢复必须使用核对过的迁前数据库及文件备份。保留新旧站点，旧站不停止、不删除。


## 归档行与手动关联（报告字段）

- 旧库 `archived_at` 非空的行迁成新系统“已归档”（状态取 `ARCHIVE_POLICY.archivedStatus`，保留归档时间/人/原因/归档前状态），最后一步写入；报告 `archived.total/byType`。
- 旧 `resource_links` 里的合作人⇄执照/店铺/银行、执照关联运营、手机号⇄店铺/执照/自媒体/微信、店铺⇄微信、账号与服务⇄执照/店铺/手机号，迁成 `relation='manual'` 并带 `valid_from/valid_to/purpose`；已被字段承载、重复、对象未迁入的跳过并在 `links.skippedReasons` 给出原因。商标授权店铺、账户店铺已是子资源，不在此列。

## 兼职与临时工

旧 `employee_workforce_profiles`（按员工，无公司列，经员工→部门确认公司）迁成“兼职与临时工”资料，来源编号用员工编号：用工类型、姓名、停用状态取自员工表（员工已停用的档案迁成停用），计薪方式/单价（旧元→整数分，精度超范围的整条不迁、不舍入）、合作期限、联系方式、备注直接对应；旧 `employee_workforce_attachments` 按分类（合同/身份证明/银行卡收款码/体检资质/其他）放进对应附件字段。迁入只写资料本身，不改员工账号、不写薪资记录、不触发停用交接（员工由账号迁入流程建好，档案排在人员之后）。旧档案没有合作开始日期的，档案缺开始日期会进失败清单待补，不填假日期。
