# 直播下播数据图片、互评与独立工资

用户要求核对中控先上播/主播后报、双方分别下播及各自计薪；人事可二次修正时间重算。新增中控下播必须上传本场直播数据图片，主播和中控给其他实际参与人员以0～10分滑杆评分，并在审核留存。用户明确确认评分只针对本场实际参与的其他人员、暂不影响工资。

## 业务行为

- 后台原有按sessionId加入同一场次的能力保留。本分支已合入前一任务PR #294的旧排场入口修复，包含打开时、提交前和并发冲突后切换实际场次再核对；补测主播/中控两种先后顺序。发布时需保留main现有排班限制、弹窗固定底栏和手机布局。
- 正常主播、中控各自打卡并各自下播，按确认点击的服务端时间记录；不能代另一人操作。试播主播原有中控具名代理规则保留。
- 工资默认读取live_session_checkins各自的起止时间；人事可分别修改主播/中控计薪时间、试算并审核。原始打卡不被覆盖，工资review_snapshot保留原始时间、修正标记、审核人和说明。传统运营兼中控仍只计提成。
- 新增attendance原始记录供直播详情、直播审核及流程待办审核核对；修正表单占位时间改为对应人员的真实打卡时间，流程表单帮助文案同步澄清。
- 中控实际下播至少1张、最多10张图片，每张不超过10MB，仅png/jpg/gif/webp。沿用FilesService真实文件头识别及存储，专用上传/签名下载入口复用本场可见权限；上传只允许本场已打卡中控，图片限定公司、场次、类型、字段和上传人。
- 评分对象仅来自本场实际打卡且仍对应本场角色的其他人员，排除本人和未参与人员。每人均须明确选择0～10整数分，0为有效分数，不默认填分，不影响工资和提成。
- 下播时在同一事务中校验图片/评分并保存到本人checkin confirmation_json.checkoutFeedback，保留原上播及试播代理确认字段。保存服务端人员姓名/角色快照和提交时间，追加审计before/after。
- 直播详情、直播审核、流程待办审核展示原始时间、数据图片、评分人、对象与分数。图片可放大。审核/锁场后不能修改。
- 保留首人下播30分钟后锁场、原订单退款核对、流程审批及人事补报规则；历史人事补报不被隐式改写。
