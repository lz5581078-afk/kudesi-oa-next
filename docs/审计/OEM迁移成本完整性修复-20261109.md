# OEM 迁移成本完整性修复

旧供应商 OEM 的 `purchasePrice` 是含包材总采购价，`rawMaterialPurchasePrice` 是独立原料价，`production_bom` 采购记录可能仅包含包装。旧迁移器因避免重复 BOM 而整个删掉采购输入，造成只剩包材和运装。

## 改动

- OEM 只迁明确原料价，并核对已提供的原料、包材和总采购价一致性；不从总采购价或 BOM 猜原料价。其他类型仍按有效成本记录口径。
- 独立成本核算和验证恢复均要求 OEM 原料依据；缺失或矛盾不能作为零元通过。
- SKU 修复只补当前为空且具有已知错误迁移标记的采购价；人工变化保留为冲突。空跑报告、目标指纹及事务回滚保护保留。
- 迁移模式会抑制正常自动基础编码同步，因此显式刷新已有相关基础编码及组合成本历史。保留编码、旧审核事实，不自动审批或触发聚水潭发送。
- 新增只读 `scripts/migration/audit-oem-costs.cjs`：对私有来源/目标快照核查采购历史、同公司引用、马甲和组合传播。输出候选，不执行写入。

## 核查

生产只读：390 商品（66 OEM），381 基础编码，560 组合。259 条历史基础编码按保留的原始来源独立重算，66 条差异均属于 OEM 原料漏项，其余193条一致；122条后来生成的基础编码没有对应旧迁入行，相关商品未发现同类采购价缺项。66个OEM的明确原料价均与最近采购价历史相符，关联66基础和63组合。2398条相关原始来源通过完整性摘要校验。

其他29条历史成本重算记录为4条基础和25条组合，不属于本次OEM漏项；不把所有旧缓存差异都当错误。标签纸0.0009与聚水潭0.0008属于来源报价差异，不擅自回退。本次未全量证明所有历史报价的业务正确性。

私有逐项文件：Downloads/jst-correspondence-20261109/oem-repair-audit.json 和 oem-repair-plan.html。不提交真实商品明细或密钥。

## 验证与限制

- Node20 根常规测试：shared459、API553、web2113、agent95、desktop19通过；数据库默认跳过。第一次未配置测试环境；之后前端默认并发导致3条既有长列表用例超时，限定2个进程后全量通过。
- 隔离本地MySQL专项22项通过：OEM漏项复现、空跑回滚、正式修复联动、重复执行、现值冲突、缺失依据、防伪造成本证明、编码保持、组合实时和最新历史成本一致、零出站任务，以及原成本精度和采购历史回归。
- 额外只读核查/映射/独立核算10项通过。
- 生产数据未修改；未合main、未部署。正式写入仍需遵循生产只读规则的明确例外授权，并先备份、空跑核对、使用同一报告受控执行，保留人工改动和旧历史。
