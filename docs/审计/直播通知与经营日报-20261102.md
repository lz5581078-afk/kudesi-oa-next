# 直播通知与经营日报

开发分支 `feat/live-notifications`；本轮仅开发、提交 integration，不发布 main、不发送真实测试消息。

## 通知分工

| 环节 | 助手与接收人 |
| --- | --- |
| 排场新增/调整/取消/移出、开播前30分钟 | 沿用直播助手、本场受影响人员 |
| 上一场下播交接 | 直播助手、同房间下一场人员（两小时内，包含已到开播时间的待接场） |
| 未上播5分钟、超预计下播10分钟 | 督促助手、本场人员；持续30分钟升级房间负责人 |
| 下播30分钟缺报告或未提交 | 督促助手、缺报人员；齐报则主播/中控任一人提交；持续两小时提醒负责人 |
| 审核/结算审批待办、退回、重提、完成 | 统一流程引擎及流程助手；直播流程超时走督促助手 |
| 审核通过及退回的其他参与人、人事补报修正 | 通知助手；跳过已收到流程结果的申请人 |
| 结算确认 | 通知助手、结算涉及员工的个人消息，正文不含金额，明确结算确认不等于工资发放 |
| 店铺聚水潭授权7天内到期/过期 | 系统助手、配置的接口负责人；永久/未知日期不推断到期 |
| 实际订单/售后查询连续失败 | 系统助手、配置的接口负责人；至少3次且持续5分钟，同一接口每天一次，成功重置连续失败 |
| 每日经营日报 | 经营助手、配置的直播查看人员；默认北京时间09:00，可改0–23时，汇总昨天 |

## 配置和口径

在「直播管理 → 通知设置」首次保存后开始扫描新场次。原有排场、开播前提醒、统一审批通知继续由原功能负责；新增通知开关控制交接、异常、结果和日报。首次保存或关闭后重新开启以当前时间作为监测起点，不补发之前的历史场次催办。日报默认关闭，开启必须选收件人。

日报仅包含场次、已审核销售额、已记录投流、已审核ROI、低于规则ROI阈值及待处理数量。按场次/平台去重，不将不同员工角色的提成记录重复累计。销售额不是聚水潭实时净营业额；晚审核的数据以页面为准，不自动重发日报。没有投流、投流未知或分母为0不输出虚假的ROI。个人工资、提成不进入日报。

日报接收人须有直播查看或直播管理权限；接口异常接收人须有接口设置查看权限。公司、停用状态、主副岗位权限及个人拒绝均服务端校验。已有通道接收人可作为初始选择；不改机器人凭据和飞书发送开关。通道继承主应用时，实际机器人仍取决于已有通道设置。

新增消息与业务事务、站内通知及飞书outbox同事务提交。新增事件表同时防止站内和飞书重复；发送前复核开关、收件人、权限及异常是否已解决，改排场、上播、补报、提交、授权续期、接口恢复后抛弃过期队列消息。飞书仍要求既有绑定通知设置、总开关和助手通道已启用。
