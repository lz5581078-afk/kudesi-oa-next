# 全员取消飞书关联并强制重绑

用户要求将当前已有的关联全部取消，让员工下次登录走强制重新关联。本次范围仅为当前登录管理员所在公司，包含管理员本人、正式、兼职、临时、已停用员工以及旧应用关联；不删除 OA 员工账号，不变更密码或公司通知开关。

人员页新增仅公司管理员可见的批量入口。服务端重复核验有效管理员身份；预览公司、人数、条数、是否包含本人，使用绑定记录摘要防止预览后范围变化。执行事务锁定公司及绑定范围，取消本公司全部关联并清除旧 OAuth 状态，写一条带人数及员工编号的审计。绑定完成事务共享公司锁并重新检查授权状态，避免取消前已在交换身份的回调恢复关联。其他公司的绑定及授权不受影响。无结构迁移。

执行后旧 JWT 继续请求业务会收到 FEISHU_BINDING_REQUIRED，登录恢复和密码登录均显示绑定要求。重新绑定仍只允许本企业飞书且一人一号，成功写 oa_notifications=1；实际推送仍受公司总开关和助手配置控制。取消后需先用 OA 账号密码登录再授权飞书，管理员本人同样需要重新绑定。

验证：类型检查、常规全工作区测试、构建和发布控制器 21 项通过；独立 MySQL 的取消关联、权限、强制绑定真实 HTTP/JWT、原通知功能和接入专项 6 套/40 项通过，覆盖在途回调取消和新授权开启通知、其他公司隔离、管理员与兼职及停用人员范围、范围变化拒绝、严格 DTO。生产发布和实际执行结果另行补记。
