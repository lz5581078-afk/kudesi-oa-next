# 主播先上播后中控确认失败

用户报告主播先点上播后中控无法上播；说明来自飞书扫码确认页，并提供完整截图。截图URL为/features/live-desk，弹窗标题「报上播（按排场）」，返回「本场已经开播，请打开实际场次核对信息后确认本人上播」。

## 根因和修复

后台已支持按sessionId加入同一实际场次。错误页面仍按scheduleId提交创建开播请求，后台正确拒绝重复开场。前端StartDialog在有预填排班时直接使用旧排场，普通开始入口也只列scheduled排班；页面打开后别人先上播同样会出现竞态。

本次只修改StartDialog和测试，不更改后台权限、公司隔离、打卡计时、首报锁场、审核或工资规则。

- 打开任意开始弹窗均先读取本人可用排班和可加入实际场次，按房间、同一排班及服务端角色资格匹配。已开播时使用JoinDialog，展示实际人员、账号、店铺和产品。
- 无预选排班时并列提供可加入场次；保留来源分支现有临时开播行为，不扩大资格。
- 提交创建前再查实际场次。若别人刚开播则切换确认页，清空旧表单确认，要求用户重新核对后主动提交。
- 若极短竞态仍得到409，只重新读取同一排班/房间且允许本人身份加入的场次；找到后显示实际确认页，不自动POST。其他错误和不可加入情况保留原错误。
- 最终加入按sessionId提交。原先扫码动作携带令牌和服务端验码逻辑保持，后台不变。
