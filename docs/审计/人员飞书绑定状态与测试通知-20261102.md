# 人员飞书绑定状态与单人测试通知

用户要求补上指定员工测试通知，并在人员中显示绑定状态，包含兼职。结合上文，此处“绑定OA”按本人飞书账号与OA员工账号的绑定关系实现。本轮仅开发并提交integration；不发布main，不发送真实测试消息，杨兰的实际测试发送仍待功能上线。

## 使用

「人员档案 / 员工与权限」新增“飞书绑定”列：已绑定绿色、未绑定黄色，同时显示个人OA通知是否启用。公司飞书未配置或读取失败显示未能确认/未读取，避免错误判为未绑定。支持按绑定状态、用工类型筛选，并可手动刷新。正式、兼职、临时人员使用同一份员工数据，不按是否已有登录记录或是否有登录账号排除人员。

有人员查看和编辑权限的人，可在员工行点击“测试飞书通知”。弹窗先显示接收人及固定测试内容，点击发送后由既有通知助手出站队列投递，同时保留OA站内通知。正文仅表示测试，不产生审批、工资、任务或业务单据。入队、发送中、成功、失败、取消和开关暂停分别显示；成功仅表示飞书接口确认，不表示本人已读。自动查询最多90秒，之后仍可手动刷新。

同一HTTP请求重试复用请求编号，不重复写OA通知、出站任务或审计；同一员工一分钟内限制重复测试。测试有效期10分钟，失败只尝试一次，不自动反复发测试消息。普通业务通知保留原有重试策略。

## 边界

- 接口身份和公司只取登录身份；状态查询需org.staff.view，发送/结果查询需同时有org.staff.edit，服务再次校验。
- 绑定必须匹配当前公司、飞书应用和企业租户。列表与发送均不返回open_id、union_id或密钥。
- 不绕过员工OA通知标记、公司发送总开关、公司授权开关和通知助手通道开关，也不自动开启它们。独立应用缺少统一身份时提示本人重新授权。
- 发送前再检查员工/公司的启用状态、当前绑定、通知标记及有效期。排队期间解绑、关闭个人通知或停用后，不投递旧测试。
- 发送仅允许固定内容和指定员工路径，拒绝正文、公司身份等额外请求字段。结果仅可查询本人发起、属于本公司和该员工的测试，不返回底层错误或凭据。
- 站内通知、出站任务和审计在一个事务中写入，预检失败不留下假成功记录。无数据库迁移，不改绑定/解绑规则。
